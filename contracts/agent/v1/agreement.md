# Frame v1 的行为约定

本文件解释 [OpenAPI](openapi.json) 和 [JSON Schema](contracts.schema.json) 的使用语义。接口字段、错误码及可选项以这两份机器可读文档为准。

1. **会话、作品和版本分开。** 一个会话可容纳闲聊和多件作品。草稿修订是独立事实；读取和反馈不产生认可。认可针对明确作品、阶段和版本，不能把后来的修订自动加入确认区。多片段的目标和依赖按具体修订引用，不按列表位置猜测。
2. **命令与回复。** HTTP 写请求携带工作台安全头和匹配的 Origin。带命令身份的操作按契约重放；请求的预期版本和目标限制作用范围。Pi 可以解释意图、交付草稿和准备提案，模型回答本身不能签发付费许可。
3. **正式受理。** 在用户认可相应输入、实际看到范围与费用，并针对提案明确确认后，服务端一次绑定提案、冻结的源版本与模型配置、授权和运行。认可方案但暂不制作不启动任务；无关对话、旧提案或已改变的输入不能沿用为新的授权。改变默认模型不改在途快照。
4. **后台动作与费用。** 生成、等待、取消、供应商费用和最终产物是不同事实。终止本地后续动作不证明供应商未收费；额度占用和实际账单也不是同一个值。结果不明时保留尝试及可用任务身份，不能靠猜测再发一次付费创建。
5. **交付与恢复。** 产物修订和对应回执/事件一起持久化；制作结果先成为待用户认可的草稿。浏览器先取快照再用游标订阅事件。流断开按公开游标恢复，失效游标按协议重读；不靠内存消息或聊天文字推断已制作、已确认或已结算。
6. **媒体与设置。** 二进制通过获授权的 blob 入口读取；对外视图不暴露本机文件路径。用户可以在受保护的配置页面查看自己的连接凭据；普通聊天、公共健康检查和事件都不应回显 Key。查热歌榜与取得可用音频是不同的工具行为。

# VideoFactory 网页性能验证

## 核心操作

测量已登录用户，不把登录页、骨架或未就绪的按钮当作完成。使用同一份只读本地受控数据，模型等待不计为网页提速。

| 操作 | 起点 | 真正可用的终点与检查 |
| --- | --- | --- |
| 创作台 | 冷缓存导航 | 作品概况已加载、四入口可用、中文字体已完成；点击入口可打开对应页面 |
| 制作记录 | 冷缓存导航 | 记录列表与搜索框出现，无加载占位；输入关键字能保留并过滤 |
| 制作工作区 | 冷缓存导航 | 当前制作与步骤已加载、无主加载占位，中文字体已完成；交付可读 |
| 编辑与意见 | 点击或输入 | 编辑器可输入；保存/发送状态真实反馈。外部执行时长独立记录，不改模型调用与审计规则 |

## 护栏

保持现有字体、配色、布局、内容、键盘操作、用户确认、版本、费用与 unknown 零重发语义。不引入占位假可用、自动审批、付费平台依赖或新的服务器基础设施。不在性能脚本里推进制作或修改生产数据。

基线先跑功能冒烟、可见文字逐字比对、1440/390 两宽度截图；优化后同样比对。路由按需加载如遇文件加载失败，必须有明确重载出口，不能白屏。保留编辑草稿恢复。

## 目标与口径

目标：核心冷启动可用 p75 降低 50%。Fast4G（RTT 20ms，下行4Mbps，上行3Mbps），所有请求含本地均限速，CPU不限速，每组至少10次，新浏览器 context 与禁用HTTP缓存。报告p50/p75/p95及长任务、请求数、传输字节。

最终A/B两份构建同时提供服务，同一时间交替各测10次。不把不同负载/压缩配置/生产数据量下的绝对值混成同口径。生产前后另外采样；CrUX不可用则如实保留，不用Lighthouse代替。

测量实现沿用 huashu-flash 的 bench.py 协议和 ratchet.py。Python浏览器依赖下载连续无进展，停止安装；用已安装的Node Playwright等价实现冷context、CDP限速、requestAnimationFrame就绪、分位数与A/B交替。登录仅限合成本地账号，认证信息只在内存，不写测量文件。原始数据及截图留本地证据目录。

## 发布与回滚

用户已批准验证后提交、推送和Actions部署。不改DNS/CDN/托管配置。每个有收益的优化独立提交；回滚使用对应代码提交的revert，经相同CI部署，不回滚或清理制作数据。

当前执行事实与其余验收只记项目现有REPORT；本目录只保存性能协议、证据摘要及可重跑工具。

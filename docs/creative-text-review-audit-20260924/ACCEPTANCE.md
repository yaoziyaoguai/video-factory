# 验收卡：先失败、再修复、最后端到端核实

执行端须在 `RESULT.md` 逐项填 `PASS / FAIL / BLOCKED / NOT_VERIFIED`，附测试命令、退出码、断言或截图/runId。只绿局部测试不能填写整个项目 PASS。测试名可依仓库约定命名，但下列行为不能省略。

## A. 合同与模型调用次数

| ID | 必须先写出的失败场景 | 修复后预期 |
| --- | --- | --- |
| A01 | 对 `topic-ideas`、`series-roadmap`、`creative-treatment`、`script-draft`、`director-plan`、`publish-copy` 和启用的 `reference-grammar` 分别走初稿。 | 每个内容交付一次有效产稿＋一次独立审计＋人工停点；`repair` 建议不触发自动修订。不得只测三阶段。 |
| A02 | 对上述各节点明确发送一次修订，观测 task kind 调用。 | 本节点只产一版，`role-audit` 调用零次；新稿显示未审，run 不自动推进。 |
| A03 | 用户手工保存、采用备选、恢复旧稿内容。 | 创建新的不可变版本；不自动审计；原审计仅属历史。 |
| A04 | 对未审修订稿按“采用当前稿”并通过所有硬校验。 | 本节点产稿/审计调用均为零；决定记“未审采用”，不复用旧评分、旧审计身份或虚构 `pass`。下游可正常生成自己的首稿/首审并再次停人。 |
| A05 | 用户点“审计当前版本”。 | 只审该精确版本一次，不产稿、不推进；完整保存新旧审计记录。 |
| A06 | 已审初稿点“采用当前稿”。 | 当前节点不再审、不再产稿；硬限制仍执行。 |
| A07 | 系列开拍检查发现普通质量问题；发布文案分别走 `write()`/`writeDetailed()` 真实生产消费者。 | 系列不自动重写已确认单集；文案无未经首审/人定版的旁路；不为同一选题/系列动作设重复采用确认。 |
| A08 | 角色首次审计返回 `pass` 且有 advisory 意见。 | 意见仍展示，可选择加入编辑框。 |

“本节点调用次数”按 `runId + node/purpose + versionId` 统计；不要把合法的下一节点初稿首审误记为重复当前节点审计。测试需要检查实际 Broker request kind 与 checkpoint，而不仅仅看 UI 文案。

## B. 权限、版本、并发与恢复

| ID | 反例 | 修复后预期 |
| --- | --- | --- |
| B01 | 用户以“仅讨论”发送消息，假模型返回 `intent: revise` 和整份新稿。 | 宿主拒绝应用越权稿件；当前稿 hash/version 不变，错误或解释可见。 |
| B02 | 用户请求备选，模型返回完整替代稿。 | 只存备选；未按“采用备选”前当前稿不变。 |
| B03 | V1 内容 A→V2 内容 B→V3 内容 A，把 V1 审计作为迟到结果写入。 | V1 审计只归 V1；V3 未审。相同 hash 不能替代 `versionId + purpose + inputDigest + operationId`。 |
| B04 | 不同稿 hash、不同 purpose、不同上游证据/输入摘要的迟到结果；另两个页面同时改同一版本。 | 旧结果不得覆盖当前；不同命令最多一个进入副作用执行。 |
| B05 | 同 `commandId` 同 body 重放、同 ID 异 body 重放。 | 前者返回原回执且零新增模型/付费请求；后者明确冲突。回执查询在新状态 stale 校验之前。 |
| B06 | 在请求准备、已受理、结果已存、确认已存四处重启。 | 观察原请求并恢复；不重复提交模型任务，不丢稿/审计/决定，不重复推进。已受理但状态未知不能伪装“审计失败可略过”。 |
| B07 | 修改已确认构思/系列约束后查看脚本、导演、选材、报价和媒体。 | 受影响的有效确认和授权引用失效，历史与可用媒体保留；无依赖对象不误伤。 |
| B08 | 审计服务已核清失败、审计请求尚未知、创作修订失败。 | 分别显示“无有效审计结论”“仍在恢复原请求”“修订失败且旧稿保留”，不互相混淆。 |
| B09 | 旧 run 没有完整审计/版本信息；打开或迁移。 | 诚实显示“未审/历史信息不足”，零模型调用；历史原始证据不被改写。 |

## C. 返工影响范围与费用安全

| ID | 场景 | 修复后预期 |
| --- | --- | --- |
| C01 | 零媒体、旧七镜 `retain`、批准范围 `[]`，新候选五镜且前五镜视觉意图改变。 | 候选可留存为未采用提案；有效稿不被替换；不进入媒体 Provider；给用户可操作的“保留原方案/调整范围”决定。worker 最后校验继续存在。 |
| C02 | 新增、删除、重排镜头；全片视觉/节奏/声音规则改变；旧新方案存在跨镜头依赖。 | 影响范围来自内容/身份差异和闭包，不来自“是否已经有媒体”；缺映射时停人，不按数组位置猜测。 |
| C03 | 用户选择扩大范围，随后新报价超出现有授权；或素材许可/来源不成立。 | 扩围决定不能代替费用授权或事实/许可校验；未授权时新增媒体请求数为零。 |
| C04 | 已 `failed` 的范围冲突 run 恢复；另一个无关 worker 异常。 | 只对结构化范围冲突提供显式恢复，保留原失败事实和回执；无关异常不被吞成普通建议。 |

## D. 浏览器交互与历史

| ID | 操作 | 修复后预期 |
| --- | --- | --- |
| D01 | 编辑框先写用户文字，勾选 2–3 条本版审计建议，点“加入修改意见”。 | 保留原文字、顺序、换行；建议仅追加，不调用模型、不自动发送。用户可删改后明确发送。 |
| D02 | `pass` 但有建议、`repair` 有建议、审计完成无建议、未审、审计失败、请求未知。 | 六种状态文案和按钮均诚实；机器字段不作为创作者可见建议标题。 |
| D03 | 切换版本/节点后尝试发送旧建议与旧讨论范围；消息超 4,000 字。 | 旧目标不可默默应用；超长提示且完整保留草稿、不静默截断。快捷提示也不覆盖已输入内容。 |
| D04 | 连续三次修订、采用后离开当前停点、刷新并重启 Studio。 | 每版全文、审计、用户决定可回看；历史版不可误确认当前版；内容与版本身份不串线。 |
| D05 | 审计/修订等待中刷新、双页并发、弹窗打开后稿件变化、本机存储写入失败。 | 原请求恢复；stale 操作拒绝；弹窗目标冻结；未成功保存不显示“已发送”。 |

## E. 建议的现有测试入口与最终验证

先看 `package.json`、相关 workspace 脚本及当前 CI，确认命令后再执行；不要凭本文把未运行的命令记为通过。可从这些现有文件扩展，避免只新写脱离真实编排的纯函数测试：

- `packages/production-pipeline/test/creative-review.test.ts`、`codex-publish-copy.test.ts`、`production-pipeline-publish-copy.test.ts`；
- `apps/studio/test/production-joint-rework.test.ts`、`studio-service.test.ts`、`series-planner.test.ts`、`creative-discussion-panel.test.tsx`、`planning-delivery-panel.test.tsx`；
- `apps/codex-broker/test/task-definitions.test.ts`、跨进程合同与恢复测试；
- 现有 `npm run typecheck`、`npm run test:ts`、`npm run test:broker`、`npm run studio:test`、`npm run build`、`npm run test:package`；最终跑 `npm test` 并记录各阶段 exit code，另跑 `git diff --check`。

真实本地 QA 使用**真实 Studio、真实服务端、实际持久化**和可控本地 Provider 测试替身，不使用真实付费密钥、fake broker、伪造 run.json 或绕过人工按钮。至少走：①普通创作从初稿/多选修订/未审采用到下一节点并重启回看；②主动审计处理中刷新/重启，只消费原请求；③去标识化返工空范围样例在新媒体请求前停下。保存浏览器截图、runId、关键请求计数和重启前后状态。此项不等于真实外部模型、真实成片或付费端到端验收；未经另行授权不得把它们写作 PASS。

若产品代码有改动但任一相关检查 FAIL、TIMEOUT、输出被截断或未执行，最终总状态不得是 `READY_FOR_REVIEW` 或“完成”；先修复或如实标记阻断。

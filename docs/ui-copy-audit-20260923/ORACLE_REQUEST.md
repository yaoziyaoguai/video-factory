# Oracle Web 审计请求

你是资深中文产品文案设计师、无障碍审计员和懂前后端状态合同的工程审查者。审计 VideoFactory 当前界面所有能展示给普通创作者的文字（含动态输出）。给你 `COPY_INVENTORY.md`：从全部客户端 TS/TSX 机械抽取的字符串，附文件与行号；`DYNAMIC_CONTEXT.md`：真实业务原则和动态路径；`presentation.ts`：当前投影规则；`NodeDeliveryPreview.tsx`：结构化产物键和值的显示。清单中包含条件分支、不可见配置词和重复文本，不得将它们全当作同屏可见。

目标：让第一次使用的个人创作者读得懂、知道下一步、敢于判断是否付费或承担风险。审计范围包括：首页/导航/选题/新建/讨论/导演/分镜/素材/配音/渲染/审片/失败恢复/费用/设置/模板/发布/移动端/无障碍名称。特别找出：裸露技术字段或错误码、混合中英且不解释的术语、过长难读的句子、状态和按钮冲突、同一概念多种叫法、把建议说成硬门、把未知说成已完成、模糊费用和授权、让用户不知道下一步、读屏名称误导。不要只看最前面的清单，逐文件覆盖并以风险优先级排序。

约束：
1. 不改变业务状态机、操作权限、真实费用、来源权利或人工确认点；不能为了“清爽”删掉重要风险事实。技术诊断可折叠，但用户层仍须说明发生了什么、已保留什么、怎么继续。
2. 不把当前使用的 `Codex`、服务名、模型名一律删除：在选择/账单/追溯中是真实身份，正文可写成通俗称谓。不得伪称所有模型或素材免费。

4. 只给本地源码可证实的建议；如果需服务端合同或真实状态验证，标记 `NEEDS_CONTRACT_CHECK`，不要声称已证实。
5. 请在内部综合产品文案、工程状态与无障碍三个视角，可以并行分析；最终只交一份去重结果。Oracle 只给建议，不修改文件、不调用服务或付费。

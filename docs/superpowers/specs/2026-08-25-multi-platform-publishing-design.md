# 国内多平台发布与合规门禁设计

**状态：** 核心编排与合规门禁已实现；正式平台适配器、账号授权与平台化元数据待官方资质

## 目标

把已经通过技术质检和人工终审的发布包，一次选择多个国内平台进行发布。系统使用统一发布任务和平台适配器，每个平台保留独立授权与状态回执。首版使用同一条已批准成片；平台专属标题、话题、封面与失败目标单独重试属于正式适配器阶段。

“一键发布”不等于无确认自动群发。任何对外发布都必须由用户明确选择平台并确认最终元数据；没有官方开放能力或尚未获得权限的平台只能导出平台包，不能用浏览器自动化绕过平台规则。

## 合规门禁

发布规划器输出 `blocker`、`warning` 和 `info` 三类结果。存在 `blocker` 时服务端拒绝发送，不允许仅靠前端隐藏提示。

1. **AI 生成合成内容标识**：生成或合成文本、图片、音频、视频时，保留生成来源；发布时主动声明 AI 内容；视频文件按适用规则保留显式与隐式标识。不得移除供应商或平台写入的法定标识。
2. **著作权与素材许可**：每个视频、图片、音乐、字体和配音都必须有可追溯 provenance 和发布许可。未知来源、仅供个人使用或禁止商业使用的素材阻断发布。
3. **事实与热点**：热点视频必须保留来源、时间与人工核验结果。医疗、金融、法律、灾害、公共政策等高风险类别必须人工复核，不以模型输出代替事实证据。
4. **肖像、声音与个人信息**：真人肖像、声音克隆、敏感个人信息及未成年人内容需要明确合法依据；涉及重大影响或公开个人信息时升级为人工合规复核。
5. **商业内容**：直接或间接推销商品/服务时标记商业合作或广告，并对医疗、药品、保健品、金融、招商等限制领域做专项规则检查。
6. **平台规则**：标题、话题、封面、水印、时长和文件规格按目标平台独立检查。一个平台失败不得让其他平台重复发布。

## 架构

```text
已批准发布包
  -> Publish Planner（待实现：生成各平台标题、话题、封面和规格转换计划）
  -> Compliance Gate（服务端硬门禁）
  -> Human Publish Confirmation（一次选择，多平台逐项确认）
  -> Publish Orchestrator（幂等批次、并发上限、独立重试）
  -> Platform Adapters
       -> Douyin Official API（待应用与账号授权）
       -> Toutiao Official API（待应用与账号授权）
       -> Kuaishou Official API（待应用与账号授权）
       -> Bilibili Official API（待应用与账号授权）
       -> Xiaohongshu Export Package（已按人工上传模式编排）
  -> Receipt Store（平台内容 ID、审核状态、错误和重试记录）
  -> Metrics Ingestion（获批数据权限后回流）
```

## 关键约束

- 账号 token 只保存在服务端密钥存储，日志、发布包和前端响应不得出现明文。
- 当前使用 `runId + platform + requestId` 作为幂等键并持久化批次结果；接入多账号后扩展为 `runId + platform + accountId + requestId`。
- 当前持久化终态为 `partial/succeeded/failed`；正式异步平台适配器接入后增加 `draft/blocked/ready/dispatching` 状态迁移。
- 平台适配器只实现协议转换和 API 生命周期；合规判断、重试策略、审计记录放在平台无关的领域层。
- 首期默认串行发送，避免同时触发多平台限流；平台回执异步轮询或 webhook 更新在正式适配器阶段实现。
- 所有外部发布均为不可逆操作，必须保留最终确认，不提供后台定时自动群发的默认开关。

# VideoFactory Studio 视觉系统取舍

## 目标

VideoFactory 是需要长期重复操作的创作工作台，不是营销落地页。视觉升级优先保证三件事：

1. 用户一眼知道今天该做什么、当前任务卡在哪里。
2. 模型、Provider、费用、输入输出和人工修改都能被看见。
3. 高频页面在桌面和手机上都可读、可操作，不依赖装饰性特效制造“高级感”。

## 调研吸收

- [beUI](https://beui.dev/)：吸收克制的微交互、清晰的按钮反馈和复制式组件思路，不引入整套依赖。
- [BoardUI](https://www.boardui.com/)：吸收 Agent 产品的信息密度、状态层级和工作台组织方式，不照搬模板外观。
- [Fluid Functionalism](https://www.fluidfunctionalism.com/)：把动画作为状态反馈，只用于悬停、展开和焦点变化；同时支持 `prefers-reduced-motion`。
- [Watermelon Registry](https://github.com/WatermelonCorp/watermellon-registry)：参考可组合组件和页面结构，但继续使用项目已有 React/CSS 边界。
- [HeroUI](https://www.heroui.com/)：吸收无障碍、焦点态和控件一致性原则。HeroUI Pro 是付费产品，因此不复制其受限源码或模板。
- [Runway 生成视频工作流](https://help.runwayml.com/hc/en-us/articles/37425232841875-Getting-Started-with-Generative-Video)：吸收 Session、Agent、Workflow 与生成结果围绕作品组织的方式；真实画面必须比配置控件更早出现。
- [Adobe Firefly 视频编辑器面板](https://helpx.adobe.com/uk/firefly/web/firefly-video-editor/set-up-your-project/change-view-of-panels.html)：吸收 Viewer 居中、素材与属性围绕预览展开的创作工具层级，不把视频工具做成纯表单后台。
- [Rive 编辑器界面](https://rive.app/docs/editor/interface-overview/overview)：吸收“当前任务需要什么，就只呈现什么”的渐进式工作区原则；不引入 Rive 运行时。
- [Material 3 Expressive 研究](https://design.google/library/expressive-material-design-google-research)：吸收通过颜色、尺度、形状、动效和内容分组建立情感与焦点的原则，而不是把所有控件做成同样大小。
- [Apple Motion 指南](https://developer.apple.com/design/human-interface-guidelines/motion)：动效必须短促、可取消且不成为理解信息的唯一方式；频繁操作不添加冗余动画。

帖子中提到的 ThreeUI 没有找到可核验、适合本项目的稳定官方实现。VideoFactory 的核心任务是审阅、编辑和决策，3D/WebGL 会增加性能与认知成本，所以本轮不引入。

## 落地原则

- 采用“暗房导航 + 日光编辑台”而非“工厂控制台”的视觉语气：深色只留给全局导航、媒体预览和审片，长时间阅读与编辑区域使用中性明亮画布，并用紫、蓝、青绿、琥珀分别表达创作焦点、信息、成功和风险。
- 不靠更多卡片制造精致感。侧栏降低对比度，创作入口彼此留出呼吸；容器只用发丝边框和短阴影表达材质，避免深色面板与硬边框把页面切成工业数据表。
- 首页标题采用编辑感更强的中文衬线体，正文和控件保持无衬线体；字号不随视口缩放，移动端用明确断点维护节奏。
- 真实作品画面是创作产品的第一视觉资产：当前制作露出成片帧，项目档案优先显示竖屏视频，缺少素材时才使用明确的空状态。
- 页面区块保持开放，不把所有内容套进卡片；卡片只承载候选、项目、节点和统计等独立对象。
- 正文字号和节点数据提高到可持续阅读的水平，减少 8 至 10 像素的小字。
- 项目列表以成片画面为第一视觉信号，状态、当前工序和下一步操作紧随其后。
- 总配置以章节索引组织，优先呈现“能否生产”和“使用什么能力”，再展开具体参数。
- 节点工作台统一为输入、角色与模型、实际 Prompt、输出、执行证据五个视图；人工编辑生成新版本，不覆盖执行痕迹。
- 页面进入用一次 380 至 440ms 的分层过渡建立阅读顺序；运行节点用进度动效，选择和悬停只做短距离反馈。
- 所有动效都服务于层级、状态或操作反馈，并在 `prefers-reduced-motion` 下关闭；不使用装饰性 3D、背景光球或大面积渐变。

## 数字人能力边界

数字人口播不是普通视频模型的一个下拉选项，而是配音之后、剪辑之前的可选表演节点。该节点的输入是已确认的人物图片与最终旁白，输出是带口型、表情和动作的可追溯视频素材；之后仍进入现有剪辑、技术质检和人工终审。

火山视觉内容生成的 OmniHuman 1.5 支持“单图 + 音频”生成数字人视频，但它使用 CV 服务的 AK/SK 鉴权，并要求服务端可以拉取图片和音频 URL。现有方舟 `ARK_API_KEY` 只能覆盖方舟模型调用，不能冒充这套权限。系统先在岗位模型清单中如实标记该能力和缺失条件，待以下条件满足后再开放模板开关与付费节点：

1. 火山 CV 服务 AK/SK 与 OmniHuman 权限。
2. 带过期时间的私有媒体暂存地址，避免把人物图片和旁白长期公开。
3. 异步任务提交、查询、下载、费用记录与失败清理的完整适配器。
4. 人物肖像授权确认、AIGC 标识和进入付费节点前的人工确认。

## 验收口径

- 1280px 桌面和 390px 手机视口无横向溢出。
- 导航、筛选、节点折叠、输入编辑、输出编辑、引导打开与关闭均可通过键盘语义或可访问名称定位。
- 低高度桌面和手机上的悬浮引导只占 46px，不形成空白遮挡块。
- 手机端高频按钮触控高度不低于 44px，辅助文字不以 9 至 10px 作为常态。
- 旧任务即使引用已停用 Provider 仍可查看；只有新执行需要通过当前 Provider 预检。

```text

生成母片不承载文字、箭头、圈选、标签或描边。后期标注只有在输入明确声明支持时才可要求，并与无字母片分开验收；未声明的定格、变速、合成、抽帧和动画不能写成已支持。
不得虚构自有照片、采访或对照素材。真实事件、因果、实验和产品效果需可追溯依据；生成内容仅能承担明确的机制示意或情绪表达，不能补成事实证据。
```


## 12. 必须同步改的规则、输入与审计接线

### 12.1 明确替换，不能只更换 directive

- `script-draft.outputRules` 的固定“0.6–1.4 倍”改为：“有 brief.durationRange 时总时长严格落入该范围；没有时才沿用目标时长 0.6–1.4 倍的既有边界”。保留 3–24 个 scene 等当前技术边界，不在本任务顺便改架构。
- 编剧 `criteria` 和 `screenwriterAuditContext.currentRoleContract.assetExecutionBoundary` 删除“每镜只能从素材开头”“不能用后续时间段”的旧禁止，改为按实际源区间能力与母片覆盖范围判断。不能只改生产提示词，留下审计旧门槛。
- 选题字段只使用正式 `strategy`，不再写 `creatorStrategy`；不改变 canonical signal 数量或增加本轮没有 UI 合同的多角度输出字段。
- 视觉审片的拉帘示例改为：“只有时间覆盖足以判断要求区间，且确证动作未发生时才判 failed；采样不足则 not_observed 并检查已有素材。是否重新生成须先判断方案是否可执行及问题责任。”删除无条件“几帧无变化就建议重生成”的引导。
- 发布编辑不再被要求凭没有提供的最终审片材料证明已过终审；正文只能基于现有 narrations，发布资格继续由程序控制，不为这一点加新审片调用。
- 原所有 JSON Schema、审批分数、费用授权、真假证据、双审独立和局部返工边界保留。删掉的是错误或重复指令，不是质量门槛。

### 12.2 构思/编剧/导演共用能力事实

新增一个窄的输入投影 `brief.productionCapabilities`，只给这三个生产角色及它们的审计。不是新服务/表/配置中心；由当前制作已选素材池和现有执行能力形成，不能由模型自行填。

定下字段：

- `assetProviders`：投影现有素材池的 `id`、`deliveryTypes`、`supportsReferenceImage`、`strengths`、`constraints`，以及已存在时的 `selectedModelId`、`minDurationSeconds`、`maxDurationSeconds`、`aspectRatios`。不含 key、socket、登录信息、库存假设或重复费用说明。
- `editing.sourceRangeReuse`：当前执行链是否支持正常速度的母片源区间复用。
- `editing.staticEditorialCard`：当前制作是否启用了静态正式卡片能力；不是素材失败降级开关。

只声明已核实的能力，不通过摘要虚构停帧、变速、复杂合成、定制标注或动画。源区间复用能力已在当前 `renderer.py` 的 `source_in_frame` / trim 路径存在，但具体素材覆盖范围仍须执行前验证。摘要缺失/某能力未声明表示未提供支持证据，不应被审计转成“已证明不可能”。当前新规划路径应总是提供摘要；不迁移历史用户数据。

摘要优先沿用导演现有 Provider 投影，消除重复的旧能力描述。导演保留实际路由所需的完整 assetProviders；不得在同一次请求中存在两份互相矛盾的事实。摘要变动进入现有相关阶段 input digest，不另建版本管理系统。

### 12.3 保持生成与审计看到同一版本的依据

- `screenwriterAuditContext` 与 `visualDirectorAuditContext` 显式传递 `creativeTreatment`、`planningIssues` 和相同 `productionCapabilities`，保留已接受承诺、beatId、问题目标及证据引用。不是把上一个模型的自评当审计结论。
- treatment 的生成/审计都收到同一能力摘要；保留 `referenceGrammar` 的“风格参考、非事实证据”性质。
- 当前 `treatmentPayload` 还会发送顶层 `referenceGrammar`，但 Broker 的 creative-treatment 顶层白名单没有它。接入时必须同步正式类型、白名单和归一化返回值，并建立包含参考语法的跨边界测试；不能只让测试客户端接受它。
- `requireScriptBrief` 的白名单/类型/归一化新增能力摘要；同步 descriptor 中的真实输入说明，不能扩大成任意字段都接受。构思、导演同样在现有正式边界校验摘要结构和大小。
- 只调整现有 prompt builder、角色适配器和组合根，不增加一次预审、总结或协调模型调用，不取消现有独立审计。

### 12.4 三个核心角色 criteria 定稿

替换对应适配器的 criteria 数组，下面每个项目是一条。其它角色保留既有有价值 criteria，只按上面的职责/例外对齐，不再复制一份角色全文进 criteria。

构思：

1. 观众承诺具体，与用户/系列锁定目标实质一致；hook、progression、payoff 能形成完整体验。
2. 每段有新增信息、情绪或必要承接，beatId 稳定；不把段落机械等同镜头。
3. 时长遵守本次明确范围，视觉/声音原则与已声明能力相容；未知素材风险诚实记录，不要求此阶段已经获得素材。
4. 事实来源、机制示意与情绪表达分开；suppliedSourceIds 只引用已有 id，来源缺口不伪装已证实。
5. 保质量后优化复用与成本；不以说明卡、无关图库或缩水承诺假装可行。
6. 修订解决既有问题且保留已合格职责；超出本角色可解范围的问题明确指向上游，不盲目循环。

编剧：

1. 保持 creativeTreatment 的观众承诺、段落责任与 payoff；落实本次 planningIssues，事实边界一致。
2. 前两秒有具体吸引点，前六秒有与本片承诺相符的部分兑现；后段有推进，结尾不另起承诺。
3. 脚本动作、旁白、屏幕文字、声音提示与时长协调，可见成功条件具体；不靠加速或凑镜头塞内容。
4. 素材/编辑要求符合 productionCapabilities；同母片源区间方案允许在覆盖可证的前提下交导演落实，独立生成不能冒充同一对象或真实实验。
5. durationRange 优先，模板必需职责、visualPlan 和系列约束一致；冲突不能通过静默跳过或捏造能力解决。
6. canonFacts 只写已建立事实；事实阈值与条件不因 hook 或总结被改成绝对断言。
7. rework 的范围、findingId 与人工指令准确，未受影响内容保留，不宣称已经复验。
8. 修订复核上轮问题，不破坏已有兑现与能力约束；新的 blocking 有可引用依据而不是更换个人偏好。

导演：

1. 视觉圣经、逐镜职责与已接受构思、脚本承诺一致，有清楚的视觉推进而非风格堆砌。
2. Shot Spec、temporalBeats、Provider、deliveryType、提示词与成功条件彼此一致且可执行；静态不假装动态。
3. sourceInSeconds、母片覆盖、复用与参考图关系有效，实际使用区间完整兑现；多余生成尾部不改变成片时间轴。
4. 真正的跨镜身份与因果要求有执行依据，独立生成和免责声明不能伪装保证；否定句中的词语不构成肯定要求。
5. 事实证据、生成示意、正式卡片与后期文字职责分清，不混入伪标签、内部说明、虚构库存或未声明能力。
6. 选择池内 Provider 只形成报价；质量满足后降本，无费用硬上限、提前审批要求、漏镜头或失败卡片兜底。
7. 模板、参考语法、系列规则和上游 planningIssues 得到落实，不能要求逐字重复或擅自改变已接受收益。
8. rework 同时落实 visualDirectionInstruction 与 assetInstruction，仅修改授权范围并继承其余镜头；没有新审片证据不能标 verified。

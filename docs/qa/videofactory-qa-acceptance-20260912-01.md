## 2. 实际覆盖的用户路径

1. 登录（成功/错误密码/登出/服务重启后重新登录）
2. 首页三入口：热点 / 系列 / 自有想法（全部可达，引导弹窗可关闭）
3. 热点全流程：加载态 → 12 条信号（10 平台）→ 候选列表 → 分类/平台筛选 → 候选详情（内容潜力依据、来源线索、开工门槛）→ 补充来源弹窗 → 保存后重估 → 未入选原因 → "重新刷新热点"（刷新身份更新）
4. 自有想法：录入机会弹窗（手动录入 tab，字段齐全）→ 保存 → 机会详情（导演台/创意决策/制作步骤/缺失能力）
5. 系列：创建系列（名称/承诺/受众）→ 12 集路线图（第 1 季、前后集依赖"等待前集"）→ 单集详情（承接要求/兑现/留给下一集）→ "开拍前复核未就绪"门禁 + "去配置系列主理人"链接
6. 模板工坊：新建（弹窗+命名）→ 编辑字段 → 保存草稿 → 发布（确认弹窗+状态）→ 删除（确认弹窗，后果说明）→ 列表刷新
7. 创作设置：创作基线（画面策略/导演/平台/时长/人工终审）、选题策略（定位/受众/优先/避开/总编规则）保存→重载持久化、能力概览（热点 4/4、制作能力 3/14）、制作分工（各模型角色"不可用"如实展示 + "双审任一路未就绪不能开工"）
8. 新建制作向导（制作记录页进入）：00 模板 → 01 内容简报（时长范围 20–34 秒、必填项）→ 02 导演 → 03 画面策略（"不设全片费用上限"）+ 预算意向（"不是付款授权"文案）→ 04 自动制作设置 → 05 双审门禁（禁用 + 精确缺失清单）
9. 空态页面：素材库 / 制作记录 / 制作复盘
10. 全局搜索（⌘K）、账号菜单、创作向导入口、跳转链接
11. 响应式与输入：1440×900 与 390×844 截图 + 横向溢出检测（首页/topics/弹窗）、Escape 关闭弹窗、Tab 焦点顺序、移动端底部导航
12. 网络故障：服务进程终止 → 重启 → 重新登录 → 数据持久化验证

## 4. 失败项目（问题清单）

### ISSUE-001｜P1｜全局搜索对内置模板与已保存机会均无结果
- 流程/页面：全局搜索（⌘K / 顶栏搜索）— 任意页面
- 复现：登录 → 按 ⌘K → 输入"知识"（内置模板"知识解释"存在）→ 显示"没有匹配结果。换一个更短的关键词试试。"；改输入"电池"（已保存机会"QA自有想法：三种手机充电习惯的耗电真相"存在且在 /topics?mode=custom 可见）→ 同样无结果
- 预期：至少能搜到内置模板与已有机会/项目
- 实际：两次不同关键词均空结果
- 证据：截图 `screenshots/23-search-no-result.png`；复现步骤如上
- 阻断：否（可绕行导航）
- 初步模块判断：全局搜索组件的数据源/索引接线（client）

### ISSUE-002｜P2｜录入机会保存成功后无反馈、待制作计数不刷新、无后续指引
- 流程/页面：热点页"录入自己的选题"弹窗 → 保存机会
- 复现：/topics → 查看待补来源候选 → 录入自己的选题 → 填写全部字段 → 保存机会 → 弹窗关闭，页面无任何成功提示；"0 条已进入待制作区"不更新；刷新后仍为 0
- 预期：保存成功提示 + 指引"去哪里继续"（实际数据已落库：POST /api/opportunities 201，机会在"从想法开始"入口可见）
- 实际：静默成功；且跨页口径不一致——同一机会在 /topics?mode=custom 徽标为"待制作"，/topics 计数为"0 条已进入待制作区"
- 证据：`screenshots/24-opportunity-saved-no-feedback.png`；服务日志 201
- 阻断：否（可从其他入口绕行）
- 初步模块判断：topics 页机会保存后的 toast/列表刷新缺失；跨页"待制作"计数口径（server 投影）

### ISSUE-003｜P2｜"查看缺失能力"链接未定位到缺失详情
- 流程/页面：自有想法入口 → 导演控制台"制作步骤" → 新建制作（禁用）→ 查看缺失能力

- 证据：`screenshots/09-custom-entry-missing.png`
- 阻断：否
- 初步模块判断：链接锚点/分区定位（client 路由参数）

## 5. 未验证项目及原因（待授权/待配置验证）

以下流程被**正确的生产门禁**（"GLM 与 Codex 双审任一路未就绪均不能开工"）拦截，且本地环境无法配置文本模型（ZAI key 被生产模式强制删除；codex CLI 未安装），无法到达：

1. 报价展示 → 人工确认 → 自动继续（两阶段流的真实 UI 走通）
2. 追加额度 / 调整方案 / 暂不继续三动作与结构化缺口面板
3. 暂停、刷新、重开、恢复（生产中的暂停语义与 reload 投影）
4. 素材生成、素材失败停住（说明卡禁令）、素材库按视频组织与复用
5. 双模型审片、用户终审、打回、按审片建议预填局部返工、无关成果保留
6. 时长范围在生产时间轴中的执行（仅验证了向导输入 20–34 秒区间）
7. 首选/备选模型选择、推荐不覆盖手选、图片/视频模型能力分组（向导 step04 当前只显示"免费 · 不使用模型"）
8. 旧报价失效、并发编辑、响应丢失恢复（需生产中状态）
9. 真实付费图片/视频 Provider 边界（未授权，也不应授权给 QA 环境）

## 6. 用户体验总体评价

整体产品语言统一、克制、诚实，明显高于常见 AI 工具的平均水平：
- 每个不可用/空/加载状态都说明"发生什么、保留什么、下一步"（如"导览不会替你启动生产或花钱""系统只创建一份可运行的三段式草稿，不调用模型，也不会产生费用"）；
- 钱的边界表述一致且反复强调"报价并等你确认""预算意向不是付款授权"；
- 信息分层正确：主文案说人话，技术细节收进可展开区（模板"高级模型设置 0 项固定 · 展开"等）；
- 移动端有真正的底部导航而非缩放桌面布局，1440/390 均无横向溢出。

主要体验短板集中在"跨页状态一致性"与"全局可达性"：搜索不可用（P1）、保存成功后的反馈与跨页计数口径（P2）、缺失能力链接的落点（P2）。

## 7. 爆款视频工作流的薄弱点

1. **文本模型强依赖下的"空转兜底"体验**：无总编模型时，12 条热点全部停在"待补来源/未入选"，创作者从"看到热点"到"形成可拍角度"断链——兜底规则只保证据不保角度。建议：无模型时提供确定性的"角度框架草稿"（受众/收益/钩子模板引导手填），而非 0 分。
2. **系列路线图多样性**（OBS-007）：规则生成的集数标题与承诺重复，削弱"系列"作为持续爆款引擎的价值。
3. **从想法到制作的最后一公里**（ISSUE-002/003）：保存机会与排查缺失能力是两个掉坑点，恰好都在"用户决策最关键"的节点上。

## 修订（2026-09-12 追加）：对"未验证 9 类"原因的深入复查

原始报告把生产漏斗不可达归因为"GLM key 被删 + codex CLI 未安装"。复查后修正为更准确的架构级结论，并承认原始调查存在三处不足：

### 复查新查证的事实

1. **文本模型链路架构**：Studio 自身不持有任何 GLM 凭据——`apps/studio/src/server/main.ts:36-38` 无条件删除 `ZAI_*` key（注释明确"BigModel 凭据只属于宿主机 broker"）。全部角色代理（编剧/导演/构思/双审，见 `role-agent-assembly.ts`）只经 `codexClient`/`zaiCodexClient` 走 **broker unix socket**；`FallbackScreenwriterAgent` 等包装的是"多个模型候选"，不是免模型兜底。
2. **Broker 启动条件**：需要 codex CLI（本机 `command -v codex` 为空，未安装）或 ZAI key（环境无 `ZAI_*` 变量）。两者皆缺 → broker 无法启动 → 文本阶段不可用。
3. **排除的替代路径**：`VIDEO_FACTORY_AGENT_RUNTIME` / `VIDEO_FACTORY_OLLAMA_URL` / `VIDEO_FACTORY_TOPIC_MODEL` 在 shell 环境存在但**代码中无任何消费者**（遗留/前瞻变量），Ollama 服务未运行；`STUDIO_DEV=1` 开发模式不改变 key 删除（删除是无条件的），只免除认证——即换 dev 模式也无法解锁文本模型。
4. **付费媒体 key 在环境中存在**（`ARK_API_KEY`/`MINIMAX_API_KEY`/`PEXELS_API_KEY`/`PIXABAY_API_KEY`）：若漏斗被解锁，素材生成会调用真实付费 Provider——QA 到"付费确认边界"必须停（不授权、不确认），与原始约束一致。

### 原始调查的不足（诚实记录）

- 选了生产模式启动后，把生产模式的约束直接当成"环境极限"，未先排查 dev 模式差异（虽然事后证明 dev 模式也无济于事，但当时未查证）。
- 只检查了 codex CLI，未一次性排查 ZAI key、Ollama、runtime 变量等全部可能的文本后端。
- 报告未说明架构（studio→broker→codex/ZAI），"本地环境无法配置文本模型"是断言而非论证。

### 仍不可验证的结论（维持，但依据已核实）

9 类生产漏斗项目在**当前环境、不修改产品代码、不引入外部凭据/工具**的前提下确实无法通过浏览器验证——门禁拦截的是真实缺失的依赖，不是测试障碍。

### 已确认可行的解锁路径（供下一轮决策）

Broker socket 路径可经 `VIDEO_FACTORY_CODEX_SOCKET_PATH` 环境变量指向任意 unix socket。QA 可在仓库外（如 /tmp）编写独立 **fake broker**（实现 /v1/tasks 协议，响应直接复用 C 阶段测试夹具中的合法 payload：creative-treatment/screenwriter/director-plan/topic-ideas/role-audit），让能力探针就绪、门禁开启，从而在浏览器中真实走到：规划 → 方案 → **报价与两阶段确认（停在 awaiting_spend_approval，绝不确认花费）** → 三动作 → 暂停/恢复。预计工作量约 300 行协议代码 + 数轮 schema 调试，建议独立会话执行。注意纪律：全程不建授权 scope（否则 C1 自动继续会越过报价边界）、不点击任何付费确认按钮。

# 为什么第 2 次与第 7 次对同一批素材给出了不同结论

结论：**两次审片的证据集不同**，不是模型自相矛盾。

## 事实

| | 第 2 次（21:07 起） | 第 7 次（22:03 起） |
| --- | --- | --- |
| 采样帧数 | 15（每场 3） | 24（场 1–4 各 5、场 5 为 4） |
| 采样模式 | `scene_triplets` 结构（opening/middle/closing） | `scene_sequence` |
| `imageSetSha256` | `85968597aeb3bdea…` | `26cb90ee429e4eec…` |
| 图片字节 | 612496 | 973764 |
| promptBytes | 40695 | 42319 |
| 场 1 覆盖的源时刻 | 675 / 2250 毫秒等 | 450 / 1350 / 2250 / **3150** / **4050** 毫秒 |
| 结论 | `revise`，continuity 84 | `reject`，continuity 52 |

## 机制

`src/video_factory/review_media.py` 工作区里有一处未提交改动（文件 mtime 21:33，`git diff` 只有这一段）：

- 旧行为：全片预检固定只给每场加两轮采样（每场 3 帧，共 15 帧），只有试片（`pilot_review`）才用满 24 帧预算。
- 新行为：全片预检与试片共用同一笔 24 帧预算，逐场轮转补齐（场 1–4 各 5 帧、场 5 为 4 帧）。

代码注释已经写明动机：每场 3 帧时「场内的动作窗口一个采样点都落不到，审片只能如实报 not_observed，预检就会在配音与渲染前停住整条主片」。

时间线：第 2 次审片的证据在 21:07 生成（旧行为，15 帧）；该改动 21:33 落到工作区；Python 由 studio 子进程直接从 `src/` 运行，不经过构建，因此第 3 次（21:39）起的每次审片都已是 24 帧（第 3–6 次都在恢复阶段就失败，没有产生新的模型证据）。

## 影响

1. **解释了两次结论差异**：第 2 次采样只落在源 675/2250 毫秒等点，人在画，故判 satisfied；第 7 次采到了源 3150 毫秒帧，人物已离画，故判 critical。两次都是在其证据范围内如实的判断。
2. **解释了缺陷 A 为什么必然出现**：证据集变化 ⇒ 审片报告的跨字段校验（要核对 findings 与当次证据帧）对第 2 次检查点里的候选不再成立 ⇒ `restoreCheckpoint` 校验失败。这正是缺陷 A 的触发条件。
3. **证实了缺陷 C 的必要性**：证据快照确实会变，身份不绑定证据快照就会回放旧结论并与历史物理任务撞身份。

## 边界

本节只说明「证据集变了」。**没有**据此判断两次审片中哪一次的采样更合规：`MAX_FRAMES = 24` 与 `--max-frames 24` 是既有合同，改动是把没被用满的预算用满，未改帧数上限、未改模型、未改思考强度、未改评分门槛。

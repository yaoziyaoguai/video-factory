## 3. 本轮锁定的产品规则

1. 用户明确要求是硬要求；推荐/模型建议不能偷偷升级为硬规则。未选模板不后台补固定套路。
2. 模型负责创作和建议，不拥有作品最终否决权。完整负面意见供用户修改、讨论或明确承担；不能删掉原意见伪装通过。
3. 无报告、残缺报告、陈旧证据、无合法素材、不可执行规格等不能伪成功；停在有明确恢复出口的位置。
4. 每节点完成后停下，用户决定是否进入下一节点；构思、脚本、导演方案中可多轮讨论、手改、换模型。不限用户讨论轮数。
5. 默认一次逻辑复核：创建/保存新稿触发约定一次；有效报告确认不再审。用户主动重审另算一次。传输重试/schema repair 有边界并分开计数，不以“重试”名义反复改作品至模型满意。
6. 内容确认、质量承担、下一节点推进、报价授权、最终验收是不同动作。用户承担质量意见不意味着批准新增购买。
7. 优先复用已有合法媒体、免费图库、可用本地能力；不能为省钱违反用户要求、证据真实性或降低质量。免费无合适材料时如实给选择，不偷偷调用收费生成。
8. 用户暂用原 DeepSeek key。不擅自改凭据；免费额度实际可用与否需证据，文本 API 不当然免费。
9. 新 run 单 DeepSeek 视觉审片；取消双模型不取消技术检查、各角色复核和人工终审。
10. 全局配置影响新 run；在途 run 冻结配置，只有明确节点修改才影响相应依赖。凭据撤销/模型退役等安全限制仍实时生效。
11. 图库扩充作为后续需求；本轮不接入新供应商，不预设采购价格或商业授权。
12. 仅本地实施、测试和下载，不进行任何外部发布、提交或云部署。

## 4. 当前与目标交互流程

四个现有入口保持独立：热点、系列、自有想法、案例/脚本参考。不要退回旧“三入口”认知，也不迫使自有想法先选热点。

```text
任选入口 → 内容简报（用户确认）
          → 构思：生成 / 讨论 / 手改 / 复核 / 用户确认
          → 脚本：生成 / 讨论 / 手改 / 复核 / 用户确认
          → 导演及分镜方案：讨论 / 调整路线 / 用户确认
          → 素材获取（如收费先报价授权）
                试片：完整意见 → 必要时请用户决定；缺结果 → 可恢复暂停
          → 源素材审查 → 声音 → 渲染 → 技术检查 → 单模型视觉审片
          → 用户终审 → 本地发布/下载包 → 用户确认
```

每个制作节点之间的既有人工边界保留；上图不意味着后台自动穿过边界。同一已授权 assets 操作中不新增“每镜都点一次”要求。收费报价只在需要购买时出现；预算意向不等于付款。

每个停点统一回答：完成了什么、哪一版、有哪些意见、下一步做什么、是否收费、哪些内容会重做。技术诊断可折叠，错误不是永远转圈。

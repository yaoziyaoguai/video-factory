# 本地真实 QA 执行包

在实施与确定性回归通过后使用。执行端读取自己当前环境的 QA 技能全文，采用报告优先方式；与本包权限冲突时本包/用户明确边界优先。不自动提交、不上云、不边测边小修。

## 1. 权限先分清

已允许：本地实现、编译、确定性测试、免费优先的本地环境与浏览器核验。可用授权合法的已有媒体和真实免费来源；不得删改原 dogfood run。

当前**没有新的金额上限/收费代理授权**。2026-09-14 的 ¥50 不沿用，2026-09-18 历史 ¥5 不是本轮预算。“继续旧 DeepSeek key”允许沿用现有配置，不证明所有请求免费。任何收费图片/视频/TTS/文本任务前先问清本次范围和上限，不新开订阅。

确认收费只问一次具体问题，例如：“要验证从规划到单模型审片的真实链路，需要调用当前 DeepSeek API；拟优先免费素材和本地声音。你允许本次总费用多少，是否允许在该上限内由我确认具体报价？”得到授权后记入 RESULT，包括总额、范围、已用/剩余、是否委托逐报价操作；不重复重开预算。

质量意见承担和最终作品验收未自动委托给执行端。可在确定性测试覆盖这些动作；真实作品没有明确委托时留给用户，不自称用户已经看过/接受。

## 2. 安全启停本地环境

1. 重新核对 4317/4318 和 Broker socket 的实际 PID/cwd/启动方式，检查无在途请求/采购，先保存现有日志位置与健康快照。不要照抄旧 PID。
2. 活跃任务不可因构建/tsx watch 自动重启而打断。若无法安全等到停点，先问用户再动服务；不更改原 run 来腾空环境。
3. **不要直接运行 .local/dev-restart.sh**：当前含 broad pkill、kill -9、日志截断。只对已经核对属于本项目、本轮要替换的进程正常终止；保留日志，超时不要扩大杀进程范围。
4. 复用当前正式 app/Broker 启动路径，不创建 fake broker。scripts/studio-dev-with-codex.sh 当前只起 DeepSeek；名字不是 GPT。该脚本有构建和进程生命周期行为，先检查实例/socket冲突，不能叠起第二套。
5. 先做 source 本地调试，最终基于本轮正式 build 的 Studio/Broker 再验证。按现有配置传 socket/地址，不用打印 env 的办法确认 key。凭据由现有加载器读，不复制到截图/报告/测试fixture。
6. 记录运行代码 HEAD+工作树摘要、dist 构建时间、实际端口/socket、健康结果。health ok 只代表进程可用，不证明模型或媒体链成功。
7. 使用独立本轮 run/隔离测试数据；生产路径跑真实 broker，不接替身解除门禁。正式 fixtures 保留用于 L1/L2，不能当产品污染一并删除。

## 3. 先主线，后有目的旁支

**L2 必做完整主链**：四入口可参数化前段并汇入同一正式图；外部响应受控，其它 API/状态/授权/持久化真实。走到真实渲染可用产物和本地包的部分，明确哪些媒体/角色是替身，不冒充真实模型。

**L3 免费/已授权主链**：

1. 自有想法先选普通示意内容，明确非真实取证；不要用特殊题目为系统开后门。核对免费路线和素材适配，内容简报→构思→脚本→导演，每次停点、讨论/保存、确认和模型实际身份记录。
2. 素材路径优先现有合法库存/免费来源；无合适材料时记录原因和选项，不自动退到收费模型。测试报价时停在未授权边界。
3. 有合法费用授权时才测试新购买/试片；不足时系统应可请求追加、改方案或暂不继续，不能自动扩大。
4. 声音使用实际可用本地能力（如 macOS say）时记录实际声音与许可范围，不把它说成付费 TTS。做实际配音、字幕、渲染、技术检查。
5. 单 DeepSeek 视觉审片需要真实图像输入证据和完整回执；费用尚未授权则该项 blocked，不能贴模拟报告。
6. 人工终审留出查看视频/听声音/逐条意见和承担/返工动作。权限允许时可演示代理测试操作，但用户验收状态始终单独记录。
7. 本地下载包核对视频、封面/文案/来源授权资料的实际内容，不做平台发布。

**旁支最小集合**：

- 热点：来源信息够用且有完整正文/摘要证据；低分但合法内容不硬阻断。当前来源获取问题若未在本包修复范围，记录，不暗扩热点工程。
- 系列：系列硬要求进入规划，确认不丢约束。
- 案例/脚本参考：入口独立、附件/需求跟随，版权提示在。
- 同一 run 一次脚本手改/一次模型覆盖、一次刷新/重启恢复、一次局部返工；这已覆盖多项关键合同，不每次重跑整片。
- 390/1440布局，五类设置与轻新建，错误提示/停点动作与后端一致。
- 额度不足/404/断流/unknown/并发优先 L2 故障注入，不为复现故障故意反复花真钱。

## 4. 有界测试纪律

- 每种真实失败先留一份完整证据。相同输入、相同错误没有新诊断/外部状态变化，**不手工再点**。
- 应用自身有限重试计入真实总调用。需要排除偶发因素时最多再做一次诊断复现，并注明假设、授权余额和停止条件；不是每个失败默认可重试一次。
- 模型已受理且仍运行时只观察原任务；超过应用 deadline 仍无终态时保存状态，不另起同义 run。
- 主线阻断后继续能独立测试的其它项；不以假数据解锁门禁，不无休止等队列。
- QA 阶段先集中记录；仅阻断其它所有有效测试的根因可提出最小修复批次。一般问题测完后统一修，再做聚焦回归+受影响主线，不每修一行重跑整片。
- 素材审查慢即使最终成功也记录分段耗时与物理尝试：排队/首输出/输出/repair/轮询/持久化/人工等待。以事实判断异常，不临时缩超时或降低质量。

## 5. 每个问题记录格式

在 RESULT 中引用 evidence/ 下的单一问题记录：

- ID、严重度、对应 A/旧验收 ID、用户可见影响；
- 环境/build、入口、runId/revision、节点/阶段、时间戳；
- 最短复现、预期与实际、截图/日志路径；
- requestId/operationId、实际 provider/model/effort、逻辑次数/物理次数；
- 产物 SHA/复用、授权/账本/实际费用证据（敏感信息脱敏）；
- 根因 confirmed / hypothesis / unknown，引用代码与排除证据；不能只有“失败了”；
- 是否阻断主线、哪些其它项仍可测、最小修复范围、回归测试；
- 状态 PASS/FAIL/BLOCKED/NOT_VERIFIED；“能点击”不等于请求真正完成。

本轮证据放本包 `evidence/`，使用唯一时间戳文件名，不覆盖旧 QA 报告。不要保存明文密钥/完整敏感环境。

## 6. 收口说明

交付必须回答：主线走到哪里、有没有真实成片、有没有播放听声、是否单模型实际看图、局部返工是否复用、花了多少、哪些停在权限边界。

费用未授权导致 L3 未做时可报告“本地实现与确定性验证完成，真实模型链待授权”，不能写“整个项目验收完成”。不要默认保持后台无限监控/模型任务；结束列出服务状态与仍在途操作。

# Loop 024: Pre-Landing Audit And Cloud Acceptance

Date: 2026-09-04
Status: in progress

## Outcome

本轮负责把 Loop 023 的大范围产品改动收口成可发布版本。完成标准不是“代码已修改”，而是完整自动化门禁、本地桌面与移动端点击、GitHub Actions 部署、云端桌面与移动端点击，以及一条真实小额付费视频的成片验收全部通过。

## Acceptance Rules

- 发现问题先写入本 Loop 与 `output/playwright/cloud-qa/acceptance-journal.md`，完成同一轮测试后统一修复。
- 图片和视频逐镜报价并人工确认；没有全局或单视频硬费用上限。降本金额只是导演下一版的目标，不能高于或等于被退回的当前报价。
- 未核对的付费调用必须保持可追溯，不能编辑上游、重新制作、归档或永久删除。
- 素材失败必须停在对应制作步骤，不能生成未授权说明卡。所有生成图片和视频路径都必须加入禁文字、字幕、徽标、水印、乱码和内部术语约束。
- 模型只在连接、超时、限流、容量或明确服务不可用时切换。通用业务错误、HTTP 500、结构错误和质量不通过不能触发额外模型调用。
- 独立审计暂时不可用时可以保留已生成候选并切换兼容审计模型，但不能重复生成候选。
- 返工默认继承原制作不可变模板快照；模板后来发布新版本不能让历史返工失效。
- 模板、候选缓存和费用台账的持久化升级不能静默覆盖用户内容或复活旧规则结果。

## Strict Audit Findings

### VF-CA-017 — 历史模板返工被最新目录误拦

原制作使用模板 v1、目录后来发布同 ID v2 时，前端只看最新生产目录并要求精确命中 v1，错误显示“上一版模板已失效”，尽管服务端已能复用原运行的不可变快照。

### VF-CA-018 — 通用 ZAI HTTP 500 误触发模型替补

ZAI executor 把所有 `status >= 500` 标为瞬态故障，导致通用执行错误也调用下一个模型。只有 408、429、明确网关/服务不可用状态或可验证的容量错误能触发替补。

### VF-CA-019 — Direct Provider 生成路径漏加禁文字约束

不经过逐镜路由器的图片/视频 Provider 直接使用 `scene.visualPrompt`，绕过共享 prompt 编译，仍可能生成可读文字、乱码、徽标或水印。

### VF-CA-020 — 视觉审片候选在独立审计瞬态失败时丢失

视觉审片 producer 已完成、role audit 超时或限流时，fallback 把带 `pendingCandidate` 的错误当成不可切换，终止制作而不是保留候选并更换兼容审计模型。

### VF-CA-021 — 未核对付费结果的制作可以永久删除

`outcomeUncertain` 运行虽然不能编辑或重新制作，但仍可先归档再永久删除，从而丢失付费任务 ledger、核对记录和费用证据。

### VF-CA-022 — 新版选题合同仍读取旧候选缓存

选题总编合同已升级到 v3，但持久化候选缓存仍接受 schema v2，部署后可能继续展示旧规则混入的候选。

### VF-CA-023 — 用户模板与未来内置模板同版本冲突

用户为内置模板发布的同 ID 新版本，可能与未来软件升级后的内置版本号相同。现有相等版本排序让内置内容优先，用户模板会被静默遮蔽，草稿也可能无法继续保存。

### VF-CA-024 — 降本目标可以高于当前报价

“总价太高”反馈允许输入等于或高于当前报价的金额，给导演形成自相矛盾的目标。客户端、Studio 服务和核心工作流都需要拒绝该输入。

### VF-CA-025 — 历史来源与授权说明直接显示英文

Python worker 保存的配音、时间轴、成片和机器质检 provenance 使用英文固定文案。素材库展开历史任务时，展示层没有将这些稳定值转成创作者可读的中文，导致“来源与授权”混入内部英文说明。应只在展示层精确映射，保留持久化审计记录原文。

### VF-CA-026 — ZAI 能力扩展后部署健康检查仍使用旧任务清单

PR #28 将 ZAI Broker 从 3 类任务扩展到完整任务集，但 `restart_brokers` 仍按旧的 `director-plan,script-draft,visual-review` 精确校验。GitHub Actions run `33891067594` 中新 Broker 正常启动，却因健康响应包含更多任务而被误判不可用并触发安全回滚。部署校验已同步为完整任务合同，并增加回归断言。

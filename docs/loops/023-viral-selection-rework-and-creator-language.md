# Loop 023: Viral Selection, Rework Inheritance And Creator Language

Date: 2026-09-04
Status: in progress

## Outcome

本轮目标不是单独修几个按钮，而是把 VideoFactory 从“流程能够结束”推进到“能持续产出值得发布的短视频”。选题、模板、导演、素材、声音、返工和审片必须共享同一创作意图；失败必须暴露为可修复状态，不能以说明卡换取表面成功。

## Product Decisions

- 热度只是一种信号。推荐选题必须同时满足明确受众价值、可靠来源、可执行画面和适合的成片形态；每个可制作候选绑定推荐模板。
- 选题总编配置由账号定位、核心观众、优先方向、避开方向、来源标准和可选补充原则组成，不再依赖一段写死的自由文本。
- 模板是生产语法，不是主题标签。模板必须明确故事节拍、镜头任务、视觉系统、声音策略和可量化质量规则。
- 被打回的制作默认继承原模板版本、模型、画面来源、声音和导演配置。人工原因与视觉 finding 按问题类型预填到脚本、导演方案、画面素材三组要求，并真正进入对应生产输入。
- 画面模型按图库实拍、AI 生图、AI 生视频、数字人、主动排版画面和逐镜自动调度分组；服务商只说明能力来源。
- 声音通过内容 preset 提供经过校准的语速、停顿和声音质感组合；逐项数值只放在高级微调。
- 图片和视频逐笔报价、人工批准；TTS 自动执行并后台记账。没有全局或单视频硬费用上限，但每次授权只覆盖当前不可变报价。
- `editorial_card` 只能是导演明确选择的正式排版画面。素材失败、图库为空、生成失败、下载失败和复用失败都必须停止。
- 每个模型节点只保存一个首选模型；同一能力下其余已通过健康检查且合同兼容的模型构成有序候选池。只在连接、超时、限流、容量或服务不可用时切换，结构错误、业务校验失败和质量审计返修不会触发替补。图片/视频候选切换仍须重新报价和人工批准。

## Implemented

- 总编候选最多 12 条并保持类别多样；采用候选会同时选择其推荐模板。
- 六套内置模板重写为热点事实解读、知识解释、证据图解、实证演示、人物微纪录和清单挑战等不同生产语法。
- 新增 `GET /api/runs/:runId/rework-draft` 与完整返工合同；新建制作弹窗展示并允许编辑三组节点级要求。
- 新一轮编剧收到脚本要求和上一版脚本；视觉导演收到导演/素材要求和上一版导演方案；素材执行继续以当前导演计划为唯一可执行路由。
- 素材库默认按作品折叠组织；历史作品可展开，仍保留按资产查看。
- 声音演员表新增知识讲解、人物纪实、热点快讯和生活清单四套内容声音方案。
- 画面模型目录按能力分组，移除“设为默认”动作，保留“新制作推荐模型”。
- MiniMax TTS 仅在确认请求尚未提交时重试；请求结果不确定时不自动重放，以免重复扣费。系统保守记账并停在“重新配音”恢复入口，待核对服务商记录后再继续。
- 全站固定文案将 Provider、Agent、门禁、路由和节点等内部词转换为普通创作者能够判断下一步的表达。
- “其他具体原则”改为真正可选；仅使用结构化总编规则时也能保存，旧的泛化补充可以清空。
- 选题来源策略缺失或读取失败时不再静默降级，默认执行“两条独立且可打开的原始来源”；微博、百度搜索结果页不能冒充原始来源。
- 费用页把历史逐笔批准总额称为“已批准报价合计”，不再误导成全局或单视频“授权上限”；手工录入选题的默认分数标为“录入时估分”。
- 素材库标签只保留作品、搜索词、创作者和语义信息，不再把 `media_asset`、Provider ID 等内部字段展示给用户；内置高质量模板优先于自定义/验收模板展示。
- 创作设置的各接口独立回显，默认配置不再等待较慢的资源清单；制作进度、系列路线图、费用提示和错误消息继续移除 `Agent`、`Code Plan`、`Provider taskId` 等内部术语。
- 云端真实付费验收发现导演把“成片保留 AIGC 标识”误写进 Seedream 镜头成功条件，触发服务商文本安全审核。导演合同现已明确把 AIGC 声明留给渲染与发布阶段，执行器也会在发送前剔除这类非画面验收条件；失败仍停在原节点，不生成说明卡。
- 服务商在创建任务前明确返回 HTTP 或业务拒绝时，台账记录为“未提交、未计费”，不再伪装成账单未知；超时、断网和已有任务编号的异常仍保持人工核对锁。历史零调用回执可直接恢复为未完成镜头的新报价，付费证据也不再裸露内部模型 ID。
- 云端真实视觉审片暴露出 ZAI Broker 在 `ProtectSystem=strict` 下只允许写 `/run`，无法提交 `/var/lib/video-factory-zai-codex/workspace/.video-factory/codex-idempotency`。ZAI unit 现显式开放自己的状态目录；部署事务会随同一 release 安装、备份并回滚 OpenAI 与 ZAI 两个 unit，避免应用版本和视觉审片服务漂移。
- ZAI Broker 已从单一视觉审片扩展为 Code Plan 文本/视觉执行器：`glm-5.3` 通过 Coding Plan endpoint 承担兼容文本任务，`glm-5.3-flash` 继续处理带关键帧的视觉任务。编剧和视觉导演把 OpenAI 与 GLM 放在同一模型目录中，用户所选模型优先；其余一个或多个健康候选按任务适配、质量与稳定性策略排序后依次接管。每次尝试和最终模型写入不可变 trace 与节点回执。
- Oracle Web 第五档独立审计后，所有系列候选也统一通过受众、钩子、证据、风险和视频价值准入，不再由系列入口绕过门槛或固定套用人物纪录模板；通用 HTTP 500 不再自动切换模型，只有明确的连接、超时、限流、容量或服务不可用才允许候选接管。
- 人工修改导演方案会在服务端复用与 AI 导演相同的完整语义校验，并按当前素材目录重新报价；客户端伪造的费用不被信任，合法修改会令旧素材授权失效。编剧、导演和发行都读取当前有效 brief，不再继续使用创建时的旧意图。
- 每条返工问题获得稳定且不可篡改的 `findingId`；脚本、导演和素材只接收自己负责的结构化问题子集。角色执行可以报告已处理，但不得把未复验的修改写成已通过，只有新一轮视觉审片批准才算完成复验。
- 返工模板按 ID、版本和正式发布状态完整校验；失效的可选视觉审片可由创作者明确选择本次停用。模板目录读取失败支持原地重试并保留表单；手动选择证据图解会开放正式排版能力，但仍只有导演主动为具体镜头选择 `editorial_card` 才会生成卡片。
- 创作设置和新建制作统一只展示“仅免费画面”“允许付费关键镜头”两种真实策略；四个历史 ID 只用于读取迁移。失效的历史模板、声音、素材源、角色和模型都保留原值与原因并阻止开工，直到创作者明确替换。
- 总编判定为证据图解的选题会锁定来源画面与本地编辑画面，付费生成策略在界面和提交函数两层都不可用，不能绕过“不得虚构现场”的约束。
- 暂停或陈旧任务继承的 Provider、模型或素材源失效时，节点编辑器保留禁用旧值作为原因提示，并允许选择唯一健康替代或显式移除失效素材源，不再把用户困在必然被服务端拒绝的配置里。
- ZAI 的 408、429、5xx、连接与超时故障跨 Broker 边界保留为结构化 `model_provider_transient`；客户端不会重放已受理请求，但候选池可以安全切换下一个模型。公开回执只显示“暂时不可用”，不把内部 422 协议状态冒充成服务商错误。

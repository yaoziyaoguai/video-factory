# C3–C6 剩余范围

C3–C6 在本轮没有重新审计，状态为 `UNVERIFIED_CURRENT` 或 `NOT_STARTED_FOR_CURRENT_TREE`。当前仓库已有不少相关修改，但任何旧 `ACCEPTED` 都不能直接继承。

在 B4、B5、C1、C2 各自 `ACCEPTED` 前，不进入这些阶段，也不顺手修改它们。到达每个阶段时，主 Codex 应先重新采集当前源码/测试，再生成该阶段单任务卡。

## C3：热点发散、模板和偏好质量

### 用户目标

热点不是直接等于视频选题。系统应从同一热点发散出受众、问题、收益和表现方式都真正不同的方向，并给出为什么适合视频、推荐模板及理由、画面方式、来源线索和待补证。系列和自有想法仍是独立入口。

### 必做范围

- 同一 canonical 事件允许多个 `angleId`，重复角度去重；不能继续按 `signalId` 吞掉方向。
- `topic-ideas` 保持唯一任务，支持 focus/creator intent/generation nonce；刷新不重复生成，“换一批”有新 identity。
- 一轮建议 3–6 个实质方向，价值不足可少并解释，不凑数。
- 推荐只引用当前有效、兼容的模板；模板被删/改后重新推荐。
- 区分新闻事实、用户要求、创作提案、待证假设；常青教程可以借热点，但不能编造新闻事实或写关键词豁免。
- 系列保留 Bible/Canon，自有想法不强制过热点。
- 审查模板质量：叙事责任明确，shot slots 通常为建议；不增加同义模板凑数量。
- 模板 CRUD、失败恢复、重复点击不丢稿；偏好保存、重开、真实 prompt 和模型取舍一致。

### 验收

`E01-E04`、`Q01-Q04`、`U01/U05`。至少覆盖同事件三方向、同角度去重、换批 identity、常青与假新闻边界、模板 CRUD、两组相反偏好的实际模型取舍。

### Non-goals

不新建总编 pipeline、不增加第四入口、不把选题写死为固定策略、不承诺爆款指数。

## C4：低门槛主线与高级可编辑能力

### 用户目标

默认主线只呈现：选方向、看方案和费用、制作进度、看成片/修改。脚本、分镜、声音、模型、素材和技术错误仍可展开编辑，不因主线简化被删除。

### 必做范围

- 方案摘要来自当前正式产物：受众、开头、推进、结尾、画面、预计时长/范围、费用和不确定项。
- `needs_human` 根据服务端 intervention/allowedActions 区分待补来源、待确认方案、待追加费用、待处理素材和待看成片，不统一成“等你审片”。
- stale 素材显示“重新检查适用性”，明确保留和重做；不写成全部重新生成。
- 用户仍能改脚本、镜头、模板、音色、首选/备选模型；图片/视频按能力分组，Provider 为辅助信息，推荐不覆盖手选。
- 双审通过后仍由用户终审；拒绝进入局部返工，不静默发布。
- 错误主文案只说发生什么、保留什么、下一步；技术详情展开。
- 1440/390、触屏、键盘、滚动、关闭重开、错误恢复。

### 验收

`U01-U06`、`R04`、`B06`、`Q01-Q04`。不能只做截图；必须走真实状态和交互。

### Non-goals

不重做 React 组件体系、不创建第二前端状态机、不移除高级节点能力。

## C5：文本模型速度、可靠 fallback 与质量

### 用户目标

导演、编剧等文本阶段不应异常缓慢，但不能通过缩短 prompt、降低模型、thinking、审计或 schema 质量换速度。

### 必做范围

- 统计设计调用次数与实际调用次数，消除 B4/B5 已修后的重复规划/审计。
- 每个 task 记录排队、请求到响应、解析/合同校验、角色审计、修复/重试和总耗时；非流式 GLM 不编造首 token 指标。
- 只研究项目当前配置的 Codex/GLM 模型和实际支持参数；保留用户指定的强模型/思考等级。
- 两个文本模型各跑真实 planning 任务，验证 schema、语义、审计和 backup；fallback 成功不等于首选故障已解决。
- 故障注入区分：明确未受理连接失败、429、已受理未知、合法 JSON/schema 错、业务审计失败。只有安全类别按原策略切 backup。
- 比较修改前后同输入/参数的调用次数和分段延时；加大 timeout 不算性能修复。

### 验收

`M01-M04` 和 B4/B5 的真实调用计数。记录实际 model/provider/参数、request identity、失败类别和是否发生 fallback。

### Non-goals

不升级 Oracle，不查无关模型，不降低 prompt/审计质量，不把所有慢归因于模型推理。

## C6：集中 E2E、统一审计、部署与云端复验

### 开始条件

B4、B5、C1、C2、C3、C4、C5 均有当前源码下的 `ACCEPTED`，root build/typecheck/全量确定性测试无失败或未解释 skip。

### 集中本地验证

1. 通用故障/边界使用真实业务模块 + fake external transport。
2. 使用最少但互补的真实制作覆盖热点、系列、自有想法。
3. 覆盖图库/来源、生成图/视频、复用、连续动作、自然配音、双审、用户局部打回和一次真实授权追加/暂停恢复。
4. 真实付费必须以当次用户授权和合理小额为限；不人为耗尽账户。
5. 桌面 1440 和移动 390 实际点击；记录视频 SHA、ffprobe、费用/ledger、模型 trace、截图和失败原因。

### 统一审计

本地集中测试和修复全部完成后，重新完整读取当时磁盘上的 oracle-web Skill，使用当前完整材料做一次统一审计：爆款工作流、用户可用性、扩展边界、prompt、状态/授权/返工安全。审计发现的问题集中修复并回归，不按一个 finding 一次部署。

### 提交与部署

只有获得当次明确授权后才 commit/push。通过 GitHub Actions 构建并部署阿里云；不得 SSH 手工覆盖。云端记录部署 SHA、health、Broker taskKinds/model、SQLite 持久卷及权限/重启恢复，以及桌面/移动端真实操作证据。

云端桌面和移动 E2E 一次尽量测全，记录所有问题后集中修复。任何一次重新部署都必须对应明确修复集合和新 SHA。

### 最终文档

产品验收通过后更新仓库 README、部署指南和 Graphify；Graphify 只执行一次现有 `update`，不修理/重写工具，也不让它阻塞真实产品交付。

### 完成条件

`D01-D04` 和 `ACCEPTANCE.md` 所有强制项有证据。云端未部署、真实模型/媒体未跑、移动未点、Oracle 未验证或仍有 skip，均只能报告未完成。

# UI/UX 审计结论与证据

## 1. 结论

问题不是“没有设计”，也没有证据支持为本轮 UI 改造推翻工作流架构。现在已具备蓝白设计、真实媒体、讨论工作区、显式确认、移动布局和部分减弱动效支持。主要不足是：**需要用户决定的事不够集中，费用与恢复解释不够一致，长表单和长报告占据首屏，视觉及动效的规则分散。**

本包做前端信息架构与交互收口，不做新一轮生产流程重建。纯视觉问题用前后截图证明；动作、版本、费用边界必须用行为测试证明。动效必须录像和检查重入，不能只交一张截图。

优先级：P1 为可能误导决策或丢失输入；P2 为显著易用性/可访问性/视觉改进；P3 为本轮需要一起控制的维护风险。此分级不是对后端生产事故的定级。

## 2. 证据范围

证据目录记作 `E = ../ui-ux-oracle-20260923/evidence/screenshots/`；源码路径均相对仓库根目录，行号仅导航，修改前重读完整相关组件。

- **当前观察**：本次本地页面截图和 DOM/CSS 读取。
- **源码事实**：已读取当前实现，能直接说明某段行为；不等同于真实浏览器复现。
- **源码风险**：可构造的风险，执行者必须先建立失败测试；不能直接写“线上已发生”。
- **历史线索**：H01/H02，只辅助设计状态，不作现版本回归结论。
- **待验证**：完整键盘/读屏、虚拟键盘、费用未知等没有当前真实现场的状态。

基线：`main / 7eb7a84e56ebadeac4ffd774c427029fb9cc15a6`。manifest 中 23 个源码文件在本轮复核时一致。没有新付费、模型调用或完整生产 E2E。

## 3. 发现

### UX-01 · P1 · 费用说明容易把“画面免费”理解为“整条视频免费”

证据：当前 `11-new-run-desktop.png` 大字“无需现金确认”；`NewRunDialog.tsx:208` 区分视觉计费与自动计费配音，但头部 `:678` 仅用视觉条件，配音说明在 `:1241`。`RunWorkbench.tsx:1563` 的 `CurrentDecisionBar` 普遍说“如需付费会重新报价并等你授权”，未表达已授权/自动计费能力的区别。

影响：用户可能误解点击后的费用范围。**未据此断言发生了未授权扣费。**

改变：新建和当前决定采用相同概念：画面费用策略、配音/其他模型计费规则、预算意向、此次操作后果；不再作无条件“全部免费/每笔都再确认”的承诺。现有收费政策完全不变，无法获知的金额写“待确认/未记录”，不是 0。

避免回归：不把订阅模型视为免费，不增发报价 API，不扩授权。证明：AC-03，UI-02/UI-04。

### UX-02 · P1 · 恢复信息分散，用户难判断现在该等、查询还是重试

证据：`10-recovery-desktop.png` 有失败卡；本轮 DOM 记录同时出现“模型调用已停止”与“原模型任务仍在处理中”。`RunWorkbench.tsx:130` 的原任务恢复区与 `:608` 的失败操作区分布在不同区域；按钮目前已有服务端 `allowedActions` 约束。

影响：用户难理解“本地流程停住”与“远端原任务未确认”是两个维度。**没有证明 Broker 此时真的挂起或重复执行。**

改变：在当前决定区域同时说明本地停在哪、远端最后已知状态及时间、已保留成果、唯一推荐的合法动作；原任务未知时优先查看原任务，不把“重新制作”作为主按钮。

避免回归：只迁移现有 handler/条件；不得增加重试权限、自动取回或改写 run.status。证明：AC-04，UI-02。

### UX-03 · P1 · 新建表单误关后没有输入保护

证据：源码 `NewRunDialog.tsx:165,326,668,681,1254`：Esc/遮罩/取消直接关闭；再次打开会初始化字段。源码事实，**本轮未实际制造用户输入丢失**。

改变：只有用户实际修改后才拦截关闭，提供“返回填写/放弃并关闭”；不新建自动云端草稿，不往 localStorage 存参考视频或敏感配置。确认放弃后沿用现有参考视频清理；保存失败保留输入。

避免回归：初始值异步到达不算用户修改；提交成功正常关闭；提交中不重复提交。证明：AC-07/08，UI-04。

### UX-04 · P2 · 成片观看与审片决策被长篇重复摘要挤压

证据：`03-workbench-desktop.png`，`RunWorkbench.tsx:311` 同时直接展开合并摘要和各模型报告。当前真成片存在，独立复核仍有“修改后再审”意见。

改变：播放器为主体；旁栏先给“制作状态”和“复核结论”两行、当前产物、需处理条数与入口；原始长文逐份展开。保留每条风险和逐条表态，禁止用新文本模型自动压缩报告。

避免回归：完成不改写为质量通过；没有视频不得造播放器；历史双审不转成当前双模型依赖。证明：AC-02/05，UI-02。

### UX-05 · P2 · 讨论已有基础，但手机上的确认与风险操作缺少统一路径

证据：`13-discussion-desktop.png`、`14-discussion-mobile.png` 已有双栏/页签和底部确认；`CreativeDiscussionPanel.tsx:86,108` 风险确认/回退使用原生 `window.confirm`，其外观、长文本和焦点体验与应用弹窗不一致。

改变：保持“方案/讨论”及随页滚动的实际确认区。首部增加**定位到确认区**的入口，不直接批准；采用统一应用内风险确认，显示用户实际看到的稿件和复核身份。讨论可多轮，不限制次数。

避免回归：新异步弹窗打开后要冻结版本身份，过期则重新查看；不得在确认旧内容时携带最新身份提交。证明：AC-01/05/09，UI-03。

### UX-06 · P2 · 新建制作长表单的层级与编号不帮助选择

证据：`11-new-run-desktop.png`、`12-new-run-mobile.png` 有 01/02/02B 与长串配置；已有时长/画面要求折叠，不能说当前完全没有渐进展示。

改变：重组为内容目标、画面与声音、模型与高级设置三个可展开区；返工范围置顶。每区收起后仍有已选内容与费用/缺失能力提示，不减少能力。

避免回归：现有 `FormData` 读取含 uncontrolled 字段，折叠不卸载表单；保留所有显式选择、时长失焦规则和创建协议。证明：AC-07，UI-04。

### UX-07 · P2 · 设置首屏把概览和九项导航放在了具体配置前面

证据：`05-models-desktop.png`、`09-models-mobile.png`；`ResourcesPage.tsx:323` 有大概览，九 hash 分区在 `:347`；`ModelLibrary.tsx` 已具备三类模型、添加接入及角色默认说明。

改变：压缩概览，桌面用窄分区目录，手机用明确当前项的分区选择器；模型目录和“添加模型”提前进入首屏。保留九个原 hash 与缺失角色深链。

避免回归：不能把蓝色深链焦点框当瑕疵删除；不增模型协议、不触真实密钥，不把角色默认锁成本片值。证明：AC-10/14，UI-05。

### UX-08 · P2 · 素材卡的播放器控件与多层工具栏弱化了素材本身

证据：`04-assets-desktop.png` 一排三段视频均挂原生 controls；`AssetsPage.tsx:244` 每卡 video 为 `preload=metadata`。截图中圈状载入图标只是该帧，不能据此断言播放坏了。

改变：稳定预览比例、明确类型/来源/许可摘要；用户主动播放，开始一个预览时暂停其他预览。能用现有合法 preview 就用；没有封面保留诚实占位或元数据首帧，不新建抓图/转码服务。

避免回归：不自动有声播放；Unsplash 远程图片与署名要求保留；“可复用”不等于任何用途都获授权。证明：AC-11，UI-06。

### UX-09 · P2 · 首页失败任务措辞暗示必须全部重来

证据：`HomePage.tsx` 的“需要调整后重新开始/重新调整”链接实际只是进入详情；已有部分工作可恢复。制作列表截图 `02` 仅为 loading，列表本身不能凭它定论。

改变：首页失败入口用“查看并继续处理”；队列按可用事实给行动文案，没详细恢复数据时只写“查看处理办法”，不猜“可立即重试”。四个创作入口全部保留。

避免回归：不在点击列表时自动重试；不把失败计数隐藏或改为成功。证明：AC-12，UI-05。

### UX-10 · P2 · 字级、状态色与焦点处理还需要可验证的收口

证据：正文与操作说明普遍 12–13px，`studio-cplus.css:2886` 后又有覆盖。token 计算：faint/white=2.58，green/green-soft=4.12，red/red-soft=4.40；**这是色值配对计算，不是所有实际页面的违规断言**。`useDialogFocus.ts:31` 仅排除自身 `aria-hidden=true`，未排除隐藏祖先/关闭 details 的候选，是键盘风险。

改变：正文与重要决策说明提高可读性；状态文字用更深专用色；补可见焦点候选测试、回焦和手机键盘检查。保留已有焦点环。

避免回归：不只用颜色表达状态；不能因 jsdom 没布局就假定真实 Tab 行为通过。证明：AC-13/14，UI-01/UI-03/UI-04。

### UX-11 · P2 · 有进入动画，但尚未建立围绕“创作进展”的动效语言

证据：当前设置页测到 300/360/220ms 动画；reduce 模式该页 animations 为 0。未采完整录像，不能说产品无动效或性能已通过。

改变：用节点交接光轨、真成片揭幕两个标志性动效，配合轻量导航、消息、展开反馈。由真实身份变化触发，不把等待伪装成进度，不在每次刷新时庆祝。

避免回归：不重新挂载输入/播放器，不挡操作，reduce 提供等价静态信息。证明：AC-15/16，UI-07。

### UX-12 · P3 · 多层 CSS 和文件末尾覆盖容易让改动失效或波及旁页

证据：`main.tsx` 五个 CSS 顺序导入；`studio-cplus.css` 2886 行后再次覆盖讨论、工作台、制作列表、新建制作。

改变：同一 selector 的本轮声明回归已有归属块，列出所有权表；仅清理本轮触及的重叠声明。不增加第四套皮肤，不重构全局 CSS 架构。

避免回归：不用全局强行 `!important`，不删未审计页面规则。证明：AC-17，UI-01/UI-07。

### UX-13 · P2 · 浏览器存储不可用时，讨论输入和命令可能被直接异常打断

证据：`CreativeDiscussionPanel.tsx:20,41,46,54` 对 localStorage 的读取/写入不带保护；编辑器部分已有保护。是源码风险，非本次现场事故。

改变：先用抛错测试复现；保证阅读和内存输入不中断。命令恢复身份写入失败时给明确提示，不发送无法可靠重放的命令；成功后清理缓存失败不能伪装成服务器拒绝，也不能自动重发。

避免回归：不吞掉所有错误后换 commandId 重试；不新增持久化框架，不抹掉别的 run 草稿。证明：AC-06，UI-03。

## 4. 必须保留与未审计项

保留：四创作入口、真实单视觉审片链、模型三层选择、模板仅资料、源素材/成片证据分离、现有费用与幂等守卫、可用素材复用、用户关键节点确认权。

本轮没有结论：热点生成质量、Broker 长耗时根因、新视频 E2E 成功率、实际供应商账单、云端性能、移动真机键盘与完整读屏。这些不混入 UI 修改任务，也不冒充已通过。

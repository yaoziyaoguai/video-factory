# 验收矩阵

所有条目当前为 **待实施/待验证**。本包中的既有截图只证明审计输入；不得填成改造后的PASS。

## 状态与证据标准

- `PASS`：该行全部必要检查通过，有可复查文件/命令和退出码。
- `FAIL`：实际执行发现不符合，附重现、期望、实际、影响。
- `BLOCKED`：环境、权限或不可替代前置阻止检查；说明排除过什么和需要的最小条件。
- `NOT_VERIFIED`：没执行或证据不足；说明原因，不隐含通过。

证据标签：`UNIT`=确定性组件/行为测试；`REAL_LOCAL`=真实本地应用与既有数据；`COMPONENT`=仅隔离组件/测试夹具状态；`HISTORICAL`=旧证据；`STATIC`=代码/数值核对。每项可分别记录unit和真实结果，不能用一个总绿勾覆盖其中的NOT_VERIFIED。

## 2. 不变量专项抽查

这是防止UI改漂亮却破坏业务的重点，不要求再写一套后端：

1. 普通确认、接受未完成复核、终审逐条表态、费用批准四类仍用各自合同和权限；不得做“任何红灯都给继续”按钮。
2. `decisionSnapshot`与讨论的`expected*`身份完整；过期只能重新看，不自动刷新identity后悄悄重发。
3. 原任务结果未知不换模型、不新购买、不启用本地定时重试；当前handler去重保持。
4. 现有父run复用与返工范围只展示/传递，不因新UI重新规划所有东西；已有显式选项不降格成系统建议。
5. 保存只保存，讨论只讨论；新建默认等待构思确认。UI演示也不能偷偷点击真实门禁来证明“端到端”。

## 3. 性能与动效的可测目标

以下都是**实施后目标**，不是本轮测量结论：

- 同一浏览器/构建/数据，至少3次导航与展开记录。新动效在期限内结束，无由新增动画回调造成的≥50ms主线程长任务；若出现记录trace定位，不直接归咎网络。
- 记录layout-shift；加载稳定后的动画不导致内容跳动，单轮非用户输入布局偏移目标≤0.1。不能拿总和代替解释具体跳动来源。
- 常见交互从点击/键盘到可视反馈目标≤200ms（本地UI反馈，不是模型任务完成时间）；有网络延迟应立即pending且保留输入。
- 首屏不自动play媒体、不预取所有完整视频、不新增外部字体/动画资源；Network记录只读请求与已授权媒体读取，0生成/报价确认/修改请求。
- 记录构建产物前后大小。未引依赖时新增客户端JS gzip目标≤10KiB；超过需说明实际来源和必要性，不能为追数字删a11y/业务保护。
- 连续切页/页签10次、开关弹窗10次，事件处理不倍增；监听器/animation/timer的源码清理加行为测试，不能只看“内存似乎没涨”。

截图、token计算与自动检查都不能证明完整WCAG合规或生产性能；报告使用“本轮范围内通过”，不要写“全项目100%无障碍/零bug”。

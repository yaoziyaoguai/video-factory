# 设计与交互规格：Light Curated Studio，作品优先

本文件是本轮的明确设计决定，不需要执行者再选风格。根 `DESIGN.md` 仍是基础；本轮仅对下列字级、布局、状态呈现和动效作有界加强。实施完成后把实际采用的变化同步回根文档，不能先改文档宣称实现。

## 1. 视觉语言与 token

冷白纸面、石墨文字、钴蓝强调、真实媒体。保留本地 Manrope Variable / Noto Sans SC Variable。深色只用于视频监看区域。不要渐变大背景、玻璃卡、全屏粒子、营销 hero 或给每个角色涂一种颜色。

### 字体与尺寸

| 类型 | 桌面 / 手机 | 行高 / 字重 |
| --- | --- | --- |
| 页面标题 | 26 / 22px | 1.4 / 600 |
| 区块标题 | 20 / 18px | 1.45 / 600 |
| 面板标题 | 16px | 1.5 / 600 |
| 稿件、消息、关键说明 | 16px | 1.75 / 400 |
| 表单 label、按钮、表格正文 | 14px；手机输入最少16px | 1.5 / 500 或400 |
| 元数据 | 13px | 1.6 / 400 |
| 非关键眉题/时间 | 最少12px | 1.5 / 500 |

不是全站 `font-size:16px !important`。优先改真实阅读和决策区域；保留密集记录表的14px。标题不负字距；长中文正常换行，长URL/ID `overflow-wrap:anywhere`，完整ID在详情可复制，不作唯一可访问名称。金额/时间使用 tabular-nums。

间距只取 4/8/12/16/24/32/48px。手机页边16，平板24，桌面32。面板padding桌面24/手机16，面板间24。圆角控件4、面板6、弹窗8。只给弹窗/悬浮层阴影 `0 16px 48px rgb(39 50 71 / .16)`；常规卡片细线即可。

控件可点击区最少44×44px；紧密记录行允许视觉按钮较小，但命中区不小于44且不与邻项重叠。focus-visible 2px accent 实线、offset2px；选中状态不替代焦点状态。必要输入轮廓与背景≥3:1，正文≥4.5:1。

### 层级与布局约束

- 使用现有断点：≥1361 完整侧栏；901–1360 图标栏；701–900 图标栏+主要单栏；≤700 顶栏+五项底导航。
- 主容器 `min-width:0`；常规内容最大宽1280px居中，编辑工作区可占满可用宽度；不把1440截图固定成页面像素宽。
- z-index 概念统一：内容0、页内sticky20、应用header30、手机nav40、非模态提示100、modal遮罩200、modal201。先对照现有值，只调整本轮冲突，不扫全站数字。
- 正文底部预留 `手机导航实际高度 + env(safe-area-inset-bottom) + 16px`；不靠固定64px假定所有手机一致。
- 页面普通滚动；只在桌面长稿件/聊天保留明确的局部滚动区。手机稿件自然随页滚动，消息历史可限高 `32dvh`；不要稿件、外壳、页面三层抢滚动。

```text

         | [当前决定：停在哪；下一步是什么；费用影响；查看操作↓]
         | ------------------------------------------------
         | 真实作品/方案（弹性主栏） | 结论与当前操作（320–360px）
         | 视频 contain / 稿件     | 制作状态 ≠ 复核结论
```

有创意讨论时使用第3节的稿件/讨论布局，不再加第三列。没有视频时不画空播放器。竖屏视频在监看区 `object-fit:contain`；桌面可见高度上限 `min(64dvh,620px)`，让播放器控制区可达。手机视频宽度受容器约束、高度上限64dvh，完整画面不裁切。

当前决定条是上下文摘要，可定位到真正操作区域；**同一个业务命令只保留一个主提交按钮/handler**。不要顶部、旁栏、页尾各做一套状态逻辑。

### 状态与动作映射

以下是**展示优先级**，不是新的业务状态机；条件仍来自现有 snapshot、`allowedActions/options` 和 handler。多个条件同时出现时先解释资金/身份安全，再解释原任务恢复，最后显示普通阶段操作。

| 现有事实 | 主要说明 | 可突出动作（必须已有权限） |
| --- | --- | --- |
| 创意稿待确认 | “前期构思/脚本/导演方案已就绪，等你确认” | 讨论区域的“确认当前方案，继续”；保存/发讨论绝不触发它 |
| node-complete | “这一节点已完成，等你决定是否进入下一步” | 原有放行动作；说明不重跑当前节点 |
| 质量repair、低分 | “有N项建议，你可以修改或承担这些质量问题继续” | 按现有授权出现风险确认，不假称通过 |
| 审查未完成 | “复核未完成，没有有效评分” | 允许时补查或显式接受未完成风险 |
| 必要产物/许可/证据不满足、付费结果未知 | 具体说明缺什么及已保留什么 | 只展示现有补证/查询/终止等，不能凭前端加继续 |
| 本地failed + 原任务running/accepted_unknown | “本地流程已停止等待；原任务最后确认仍在处理/结果待核实” | 查询原任务；显示上次确认时间、最新查询失败，不能暗示远端已取消 |
| 原任务completed_success | “已找到原结果，无需重新生成” | 取回结果并继续（不等于批准下一个人工节点） |
| 原任务completed_failure | “原任务已明确失败，前序内容保留” | 仅按服务端许可重试失败步骤/调整方案 |
| awaiting_spend_approval / approval_invalidated | “本次画面报价待授权 / 原报价已失效” | 查看并授权当前报价；后两动作保持现有“调整方案/暂不继续” |
| running | 谁在做哪一步、已用时、最新可信状态 | 现有暂停；没有依据不编剩余时间或百分比 |
| paused/stale | 已安全暂停/上游变更，说明保留与需重算范围 | 既有继续/编辑，不暗示所有步骤重跑 |
| succeeded | “成片已生成”；另列复核结论 | 播放/下载；有意见仍显示，不写“质量全部通过” |

未知字段显示“未记录/暂无法确认”，不推测 permission。复核 summary 先用已有结构化结论和真实条目数量；没有结构化短说明时标“原文节选”，最多160个字并给展开入口，不能用截断拼出不同结论。关键风险类别、未完成和是否可继续不折叠；全文、技术标识和重复报告可折叠。终审逐条表态仍逐条完成，不默认全选接受风险。

## 3. 讨论、版本与确认

- 桌面稿件/讨论约 65/35，讨论列最小300px；≤900改“当前方案/讨论”两项现有切换语义，不挤两个250px小栏。
- 面板标题、稿件版本、复核状态、未保存提示处于同一标题区。明确区分“第N轮讨论”与“第N版稿件”。
- 手机顶部提供“查看确认”文本按钮，定位并聚焦底部说明标题；不代替底部批准、不自动切换成确认状态。输入、选中镜头、各面板滚动位置在切换后保留。
- 输入普通Enter换行，Ctrl+Enter才发送；输入法composition期间不发送。快捷建议只填文字。发送pending只禁用可能重复的命令，正文仍可读；失败保留原消息，不跳到底覆盖用户阅读。
- 新消息：用户在消息区底部附近（距底部≤80px）才跟随滚动；否则显示“有新消息，查看↓”。不要抓走键盘焦点。
- 手工修改保存、采用备选、确认推进保持独立；未保存时确认按钮禁用，并在相邻处解释原因，不只给灰按钮。

### 替换 `window.confirm` 的安全规格

仅替换讨论中的风险/回退确认 UI，不把所有正常确认变成三次弹窗。复用现有 modal/focus 习惯，可提取一个小的局部确认组件，但不要建通用流程引擎。

打开时冻结 `{runId, stage, runRevision, reviewRevision, draftSha256, checkIdentity}` 以及展示的风险/回退目标与命令body。确认时若当前身份或allowedActions已变，停止提交、说明“内容已更新，请重新查看后确认”；不能把旧文本与新SHA组合。提交继续使用现有 `commandId`、`expected*`、acknowledge/acceptQualityFallback 字段。

初始焦点在标题或“返回查看”，不是风险批准；关闭不发送命令，回焦触发按钮；网络失败不清输入，pending不能双击。回退阶段要展示原有影响范围，确认不自动跨过新阶段的人工门禁。

### 存储异常

讨论文字读写 localStorage 失败时，内存编辑仍可用，显示“本机草稿无法保存，关闭页面前请复制内容”。**待发命令记录无法可靠读取或身份无法持久保存时，不调用 `onCommand`**，说明需要恢复浏览器存储后再发；读失败不能当作“没有未决命令”，不吞异常后新建身份重试。

服务器已成功、仅清理本机命令失败：显示“操作已完成，本机恢复记录未清理”，按现有权威snapshot刷新判断，不能报“提交失败”诱导重发。失败/未知仍保留同一 commandId 的重放规则。仅处理自己键名，不清空全站存储。

## 4. 新建制作：三组信息，不新增向导流程

保持单个表单和一次正式提交，不新增跨页wizard或新的草稿API。

```text
新建制作                         关闭
先生成前期构思，等你讨论确认
[画面：免费/按方案报价] [配音及模型：当前计费规则]

返工时：本次修改范围、继承事实（先展示）

01 内容目标 （默认打开）
标题、角度、受众、平台、建议时长/范围、明确画面要求/证据

02 画面与声音 （默认收起；摘要始终可见）
导演创作立场、参考视频、素材路线、声音角色/有效设置
摘要例：自动选导演 · 免费画面 · 某声音（自动按量计费）

03 模型与高级设置 （默认收起；有问题则打开）
全局角色默认/本片覆盖、现有预算意向及其他高级能力

费用与下一步说明
取消                        开始前期构思
```

- 所有原字段逐项映射到三区，不留“其他字段省略”。执行者提交映射清单；可选参考视频归第二组，不再出现02B。
- 已有必填缺失/无效项所在区自动打开并聚焦第一个错误；用户手动折叠不能隐藏“有2项需处理”标记。
- 内容目标与未配置能力提示不能默认折叠。摘要读当前值，不能偷换成推荐值；未选模型override保持“沿用角色默认”，不写入显式override。
- 折叠用保留DOM的 disclosure/hidden 区，不能卸载 `FormData` 依赖字段。hidden字段仍参与提交但不能进入Tab序列；校验失败先展开再focus。
- 桌面最大宽980px、高 `calc(100dvh - 40px)`；固定的是dialog自身头尾，表单内容滚动。手机全宽/全高sheet；虚拟键盘下页尾可正常滚到，不固定到可视viewport覆盖输入。必要时在窄屏/短高度改页尾随内容滚动。
- 费用提示始终在首部与提交附近有短版：免费画面只说明图片/视频；自动配音按真实配置说明自动按量计费；订阅费依供应商账号，不写¥0。未知voice规则就写“配音计费方式待确认”，不虚构免费。
- 预算意向不是花费授权；已有授权、画面报价与实际支出不合成一个数。UI不能许诺所有后续费用都再弹确认。
- 提交按钮“开始前期构思”，辅助说明“生成后会停下，等你决定”；保持原创建协议字段，不改变启动步骤。

### 误关保护

仅用户编辑使dirty；异步初始化/后台providers更新不算dirty，也不能覆盖已编辑值。Esc/遮罩/X/取消统一走 `requestClose`。无改动直接关；有改动在**原dialog内**显示“要放弃本次填写吗？”与“返回填写 / 放弃并关闭”，不启动两套相互抢焦点的modal。

默认focus“返回填写”；此时Esc返回填写，不连着触发关闭。放弃才走原onClose及临时参考视频清理；返回不清理。提交成功由原成功路径正常收口，不多弹放弃框。提交失败保留每区展开/输入。无需添加跨刷新新建表单持久化，关页风险仍如实提示。

## 5. 首页、制作记录、设置

首页保留热点、系列、自己想法、案例/脚本四入口。继续工作条先作品名、当前状态、一个明确入口；failed文案“查看并继续处理”，不称“必须重做”。全局服务灯只代表实际健康信息，不扩写为所有模型可用。

制作列表沿用行布局、搜索和现有filter；主动作是打开详情，归档/删除仍是现有次级危险操作。本包不执行删除。loading、空、加载失败各不同：空态邀请新建，失败给重载入口而不是“还没有作品”。不新增远程搜索或从列表触发生产动作。

设置页桌面：页标题+最多一行能力概览，下方184px分区目录+弹性正文，目录不另造路由。九项hash保持；可在目录视觉分组“创作偏好/模型与资源/证据与出口”，不减少分区。手机：概览折叠为一行summary，原九分区用label“设置分区”的原生select选择，当前区标题与主要操作尽早出现。不要保留九个横滑标签再加一套select。

`#model-settings` 保留三类：文本生成、内容生成（图片/视频/语音）、内容理解（图像/视频/音频能力按事实）。模型卡首行名称+配置状态，次行为能力、协议；接口地址和高级参数可展开。添加接入不自动检测或付费调用。

在模型与角色两区明确三层：**全局接入 → 角色默认 → 本片/节点覆盖**；是关系说明，不新增第三处配置表。已有hash、missing参数、缺失角色高亮、到达焦点都保留。切换分区不悄悄保存；未保存已有状态若当前实现保留则继续保留，不卸载整个表单导致丢数据。

## 6. 素材库

- 顶部紧凑标题/计数/配置来源链接；工具区第一行搜索+现有类别，第二行来源/提供方及按作品/按资产。窄屏折叠次级filters，当前已用filter数量与清除入口保留。
- ≥1361最多三卡，901–1360两卡，701–900两卡，≤700一张完整卡。不新增瀑布流/虚拟列表框架。
- 预览占卡主要面积，16:10容器，竖屏素材contain、图片可按内容用contain，不能默认裁掉版权署名。类型、时长（存在才显示）和镜位浮于小型实底label。
- 视频保持原生可访问controls；有合法现成poster可使用，没有就用真实元数据首帧或银灰占位，绝不伪造预览。屏外不加载完整视频；可用已有浏览器IntersectionObserver逐步启用metadata，不做后台下载和新增服务器缩略图。
- 只响应用户播放；新video/audio播放时暂停上一个，保留各自currentTime；换filter卸载时停止旧播放。hover只有轻微边框/位移，不能作为手机唯一入口。
- 卡片标题、来源/作者、许可摘要、复用状态至少可见。原始来源、完整署名、限制、复用记录在详情可达。保持Unsplash指定URL及署名链接，不下载规避限制。

## 7. 动效规格

优先CSS，必要时WAAPI；不新增动效库。不为动画改API、不定时模拟完成。下面参数作为统一上限和节奏，改变须在RESULT给出测得依据。

统一 easing：反馈 `cubic-bezier(.2,0,0,1)`；进入 `cubic-bezier(.16,1,.3,1)`；退出 `cubic-bezier(.4,0,1,1)`。

| ID / 场景 | 触发、元素与参数 | 重入/退出规则 | reduce |
| --- | --- | --- | --- |
| M1 导航/页签 | 用户换当前项；指示线transform或opacity，160ms，反馈曲线；页面正文opacity+translateY(6px→0)，180ms | 同路径轮询不重播；不对根组件换key；取消旧动画 | 无位移，直接选中 |
| M2 节点交接光轨（招牌） | 已有会话内，权威阶段或当前有效稿件身份真的改变；当前节点下方2px钴蓝线scaleX(0→1)和opacity，420ms；新稿件标题opacity+Y(8→0)，240ms，延迟60ms | key为run+stage+有效draft/artifact身份，非run.revision；同身份不重播；快速更新取消旧动画；按钮始终可用 | 静态线+真实“已更新”文字，不闪光 |
| M3 讨论/提案 | 成功收到新消息ID后，新增项opacity+Y(6→0)，200ms；最多前3条30ms stagger | 既有历史初始化不逐条飞入；失败不假造回复；不强制滚底 | 直接显示，polite播报一次 |
| M4 展开/收起 | 用户点击；内容opacity 140ms，原生布局即时更新 | 不动画height:auto、不挂延迟卸载；收起前若焦点在内则回summary | 即时展开 |
| M5 素材卡 | hover/focus边框变accent与translateY(-2px)，160ms；按下scale(.99)，90ms | pointer fine才hover位移；不重载src，不触发播放 | 无位移；保留边框 |
| M6 真成片揭幕（招牌） | 已打开run从“无此产物”收到新video artifact，且该媒体loadeddata；监看区内部纸幕translateX(0→101%)，520ms，进入曲线；标题opacity 220ms | 仅这一真实产物一次；初始化打开旧成片不播；切run/错误/unmount取消；不遮controls、不截获pointer、不自动播音视频 | 无纸幕，直接显示真实成片和文字 |
| M7 弹窗/通知 | 用户打开；opacity+Y(8→0)，180ms；退出120ms；错误即时出现 | focus不等待动画；pending按钮保留宽度；同错误不无限toast | 即时；无位移 |

M2/M6是本轮“有表现力”的重点，不只是改hover。视觉强度来自连续的空间过渡和真实素材揭幕，不靠多彩光斑。M6只能在monitor内部使用一块与paper/monitor一致的实色幕，不能引入整页渐变皮肤。

所有动画清理timers/Animation/observer；页面后台暂停非必要效果。不要每个消息都 `aria-live` 整片重读；动画装饰 `aria-hidden`、`pointer-events:none`。除真实等待指示外，无无限装饰动画。减少动效时保留成功、失败和变化信息，不用动画当唯一信号。

## 8. CSS 所有权与修改方式

当前导入顺序 `styles.css → studio-v3.css → creator-tour.css → auth.css → studio-cplus.css` 保持。`studio-cplus.css` 是本轮页面规则归属处；把本轮相同selector的声明合到已有块并整理相邻断点，不能在尾部再堆一套覆盖层。

新增少量token放已有根token块；组件规则用原页面/组件前缀。motion集中在可找到的一段，删除本轮替代的旧动画声明，防止父子两次入场。不要用新的全局 `button/div/p` 规则更改未审计页面。若旧大文件有NUL/历史格式问题，仅记录，别夹带全仓库格式化。

## 9. 验证标准来源

采用 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 的对比、键盘、重排、焦点可见要求与 [WAI-ARIA Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) 的焦点规则。44px触达是本项目目标，比WCAG 2.2最小目标更严格。静态token、jsdom测试、真实浏览器、真实手机分别留证，不能相互冒充。

## 2. 对 §6 / M08 的独立判断

### 2.1 裁决：不接受当前收窄；接受显式单腿实现

N2 退役订阅路径，N5 取消双审。这两条都不包含“接受同厂商不同模型作为独立双审”。因此不要要求用户验收一个已经不需要的独立性削弱。

最小实现是在现有组装器/审片消费路径中显式表达单腿要求，沿用现有执行和回执体系，不新增 runner：

```text
新 run：单腿 DeepSeek 审片要求
  → 校验当前审片所需真实能力与输入
  → 同一逻辑审查内有限候选尝试
  → 一份有效、完整、绑定当前输入的回执
  → 正面意见：等待当前约定的人为确认
  → 负面意见：展示意见，允许引用回执承担后继续
  → 无有效完整回执：可恢复暂停，不伪造通过
```

“一腿”不是只允许一次 HTTP 请求；候选兜底与有限传输重试不构成第二份独立意见。取消双模型审片也不等于取消全部阶段复核、G9 编辑重审、技术检查或人工终审。对同一 assets 节点内已经获得有效报价授权的剩余镜头，仍按原合同决定是否继续；不新增每镜人工停点，也不凭重试成功扩大授权。

### 2.2 实现必须满足的条件

- 不存在双插槽占位、undefined 回执、复制回执凑数或“单审但仍显示独立双审”的文案。
- 候选合格与否按实际任务能力判断；不能仅凭 modelId 名称推断图像输入能力。
- 审片模式和输入/规则身份可追溯。优先复用已有 workflow feature/version，不另建平行状态存储。
- 历史双审事实原样保存。新政策只作用于新 run，或在用户明确选择并记录的迁移操作后作用于历史 run 的未完成部分。不得回填不存在的旧回执。
- 退役的是实际 GPT/Codex 执行路径；历史记录仍可只读解释，不得为了清理字符串删账本。
- `source_review_retry` 的普通 approve 禁令保留；“审片未完成”不能伪装为可承担的负面意见。

**M08 修订方式**：生产单腿路径验证审片基数、输入身份和没有伪双审；候选池验证 canonical identity 去重。若历史双审校验器仍需保留，保持原强语义，仅用于兼容校验，不因新 run 单腿而放宽。不得把历史双审执行重新接回 GPT。

若未来委托人重新要求同厂商多模型评议，应作为新需求说明其不提供跨供应商独立性，再单独审批；本轮不做，也不建议新增付费订阅。

## 3. 必须先统一的实施合同

### 3.1 五类决定不能合并为一个 approve

| 决定 | 合同含义 | 不产生的权限 |
|---|---|---|
| 编辑/配置保存 | 提交新的内容或执行偏好 | 不自动批准下一节点，不自动付款 |
| 审查意见承担 | 对具体完整回执作出内容决定 | 不补造缺失审查，不扩大采购范围 |
| 进入下一节点 | 当前边界的执行许可 | 不等于最终作品验收 |
| 报价授权／授权代理执行 | 对具体报价、对象与尝试范围给出费用许可 | 不等于质量通过，不覆盖新报价/新 run |
| 最终人工验收 | 委托人接受或要求修改作品 | 不能由分数、技术测试或 coding agent 代签 |

N3 的实现应优先在既有授权记录里表达 principal、执行 actor、委托来源、quote/revision、run/对象、provider、金额与尝试上限、有效范围及撤销状态。已有等价字段则复用，不建设新授权平台。原话未明确的未来额度不能被扩成无限授权；UI 不能只保存一个永久的 `agentMayApprove=true`。已有足够委托范围证据时，可以由受托 agent 提交该范围内的报价授权，无需用户重复批准同一笔；这里限制的是越出委托范围，不是否定 N3。

F 记录的配音“按量自动执行”必须核验实际授权合同：若已有合法、范围明确的授权，按合同执行；没有则在现有费用边界停下。不能仅因为付费画面受控，就断言全部费用受控。文本请求也不当然免费。

### 3.2 新设置的最小模型

五类是导航视图，不是五份重复身份。一个候选可以出现在文本和多模视图，但指向同一 canonical identity、同一凭据/额度范围和能力声明。

建议有效设置规则：

```text
执行某节点时：节点显式覆盖 > 创建 run 时冻结的角色设置快照
创建快照时：用户已保存的适配角色/类别默认值 > 系统合格默认值
所有选择：先按任务能力与合同过滤，执行前再检查退役/授权等硬边界
```

全局设置只影响新 run；应用到当前 run 必须是显式操作，显示真实失效集合。安全性的退役/凭据撤销不能被旧快照绕过。页面分别展示“用户选择”“本次有效配置”“实际尝试及原因”，不可把三者混成一个 modelId。

### 3.3 错误和可恢复性

复用现有错误类型，至少能区分：请求合同错误、候选不存在/不合格、endpoint 错误、凭据问题、账户额度问题、暂时限流/服务故障、输出无效/超限、未知受理/计费结果。

同账户 402 不轮询同账户其他名称；无独立且已配置的合格候选就暂停。429/503 依据 adapter 可证明的作用范围和预算处理，不保证立刻恢复。未知 endpoint 404 不推断模型退役。付费或可能计费操作的受理不确定沿用核账边界，不把“文本调用没有媒体产物”理解成零重复费用风险。

## 4. 单会话实施计划

### 执行规则

以下 **30 个步骤是验收单元，不是要求 30 轮大开发**。已实现项只补断言和证据；不能为制造 diff 重写。每步先补最小复现或防回归，再修行为；“先解除阻断、再补测试”不意味着修复阶段不写测试。

预估规模按文件和场景表示，不承诺耗时：S＝通常 1–3 个生产文件、4–8 个断言场景；M＝通常 2–5 个生产文件、6–12 个场景；L＝通常 4–6 个生产文件、10–16 个场景。测试/证据文件可另计。若发现必须越过该步合同边界，拆出子步，不把会话扩大为通用重构。

所有测试须从现有外部 provider/transport 接口注入受控响应，保留真实组装器、状态机、HTTP 处理、授权守卫和持久化。不得把待验证的审片器/恢复器整体 mock 成“成功”。

下面文件名使用附件提供的 basename；有同名文件时在仓库按符号定位，不按旧行号猜测。新增证据文件是计划产物，不表示已经存在。

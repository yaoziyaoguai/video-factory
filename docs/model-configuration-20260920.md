# 模型配置与真实声音审片

## 已确认的产品约定

- 模型库与角色默认是两层。模型库按文本生成、内容生成（图片/视频/语音）、内容理解（图像/视频/音频）展示；能力可以重叠，不能按角色重复登记模型。
- 角色名称不绑定 Codex、DeepSeek 或其他供应商。角色提示词与模型接入分离。
- 节点明确选择优先于本条视频选择，再优先于角色默认。全局变更不改写已经创建的制作。
- 新接入按协议复用：OpenAI Chat Completions 与 Anthropic Messages 是不同协议；图片、视频、配音继续使用实际支持的供应商协议，不声称任意媒体接口通用。
- 声音审片必须消费成片的真实音轨，并结合有时间码的画面检查发音、情绪、停顿、噪声、音量关系和音画配合。转写不等于审听；缺少模型或音轨必须如实显示未审听。
- 审片提供有证据的意见，推进主动权仍在用户；不新增无法绕过的模型质量评分关卡。

## 实施边界

保留当前 Broker 的受理、查询、恢复、幂等和结果绑定；不引入绕开 Broker 的第二条文本生产通路。密钥不回传浏览器、不进入日志和制作记录。配置读取、保存本身不调用付费服务。

现有角色 ID 仍用于历史记录定位，只修改展示名称。声音证据使用独立合同，不放宽仅凭抽帧不能判断声音的视觉合同。

## 验证要求

1. 同一个模型用于多个角色时，模型库只登记一次；能力分类与协议分别显示。
2. 添加模型后实际选择、请求协议、上游模型 ID、回执身份一致；同名模型的不同接入不能串线。
3. 保存时校验能力、接口与参数；密钥不回显，配置错误不发请求，不跟随跨域重定向泄漏密钥。
4. 模型变更不能把旧请求的查询变成新生成；不确定结果不能切换后重复执行。
5. 声音结论绑定实际音轨摘要和时间范围；未发送音频时不能出现审听通过。
6. 现有制作、报价、预算确认、媒体复用、手动推进保持不变。

## 当前状态

已完成实现、确定性回归与隔离浏览器配置流程验证；不是生产成片端到端验收。没有调用真实供应商、没有新增费用，没有提交、推送或云部署。原有 4320 服务未重启，历史制作与用户密钥未读取或改写。

### 已实现的链路

- 模型库按三类展示，同一接入在多个角色间复用；移除 `codex-default` 运行时占位卡片。角色名称不再声称必须由 Codex 或 DeepSeek 执行，历史角色 ID 保留用于恢复。
- 可新增 OpenAI Chat Completions / Anthropic Messages 接入，填写上游模型 ID、地址、密钥、输出上限和接口支持的推理参数。未指定的推理参数不擅自补值；自配模型不继承 DeepSeek 专有参数。
- 模型管理通过既有认证与 CSRF 边界进入宿主 Broker。模型配置串行原子保存，私有文件权限为 600，新目录为 700；公共返回值不含密钥。拒绝重定向，避免鉴权信息随跳转外发。
- 每个接入拥有独立身份、socket 与 durable 记录。停用后不再执行新任务，但仍能查询原请求；可重新启用。不确定请求不会换模型重发。
- 角色默认与接入分层；一个“保存角色配置”入口保存改动。默认在新制作中冻结，节点选择可覆盖本条选择；选题/系列每轮固定一次模型，生成和复核使用同一选择。
- 编剧、导演、构思、选题、系列、参考分析、候选排序、发行文案、质量复核、视觉审片已接通模型选择。排序外层身份、角色 checkpoint 和实际调用统一消费当前选择：改选模型使旧排序失效，但不重跑未变的上游角色或候选搜索。
- 最终成片的声音审片提取真实完整 MP3 音轨，结合有时间码的画面和脚本对照，返回独立声音意见。报告绑定成片/音轨摘要；prepared 请求先落盘，再按原身份恢复；缺音轨、缺配置、失败、不确定均显式呈现，不伪造审听通过。
- 声音调用的已证实次数计入回执；不确定次数保持待核实，不显示假 0。声音意见不替代用户最终决策。

### 明确限制与后续真实验证

1. 没有实测任何新供应商模型的兼容性与审片质量。“已配置”不等于供应商实测成功；接口须实际支持所选协议、参数与能力。OpenAI Responses 不等于 Chat Completions，本次没有新增 Responses 适配器。
2. 音频审片要求同一模型支持音频与图像输入；OpenAI 适配器发送 `input_audio`。Anthropic 当前适配器不提供直接音频输入。MP3 超过 5 MiB 会明确报告未审听，不截断后冒充全片通过；抽帧证据不能证明逐帧口型同步。
3. 图片、视频和 TTS 仍使用实际已接入的供应商协议；不能只登记一个文本兼容地址就获得新的媒体生成协议。新增媒体协议仍需适配。
4. 新接入支持添加、停用与重新启用；暂不支持原地修改密钥/地址或删除接入。更换时新增接入并停用旧接入，避免旧请求身份混淆。
5. 模型管理需要更新后的宿主 Broker 已启动。当前启动配置仍依赖现有 Broker 引导配置；没有把“零现有配置的全新安装”改成新的引导流程。
6. 地址校验拒绝非 HTTPS、明文 IP、localhost、URL 内凭据和查询参数；不等于完整的 DNS 重绑定防护。该管理功能面向当前受信任的个人管理员，不宣称支持不受信任租户任意地址接入。
7. 原本地 4320 服务尚未切换新版。正式切换时需一并更新 Broker 和 Studio，先确认无活动制作，避免恢复旧任务造成意外模型调用。本轮不恢复历史制作来做验证。

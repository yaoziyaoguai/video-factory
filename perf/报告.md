# 网页性能结果

本轮保留三项改动：工作区按需加载、次要页面按需加载、大制作记录JSON传输压缩。业务数据、历史、字体、布局、审批与费用规则不变。没有引入新的平台服务或运行依赖。

## 同条件配对结果

优化前为`fec1653`冻结构建；优化后含两次路由分块和HTTP压缩。两服务同时运行，同一时段交替各测10次，Fast4G（RTT20ms、下行4Mbps、上行3Mbps）、CPU不限速、冷context和禁HTTP缓存。时间终点包含真实数据、可操作页面和中文字体，不是骨架出现。

| 页面 | 优化前 p50 / p75 / p95 | 优化后 p50 / p75 / p95 | p75降幅 |
| --- | --- | --- | --- |
| 创作台 | 4625.5 / 4642.8 / 4725.4ms | 3241.3 / 3248.4 / 3283.7ms | 30.0% |
| 制作记录 | 4598.9 / 4682.1 / 4711.2ms | 3398.2 / 3409.1 / 3416.6ms | 27.2% |
| 制作工作区 | 6532.3 / 6539.7 / 6564.9ms | 4213.1 / 4221.3 / 4289.8ms | 35.5% |

测量时段：2026-10-07 10:35:42–10:41:22 UTC。A端用原未压缩API，B端用当前正式HTTP装配、只读获取相同隔离数据；后者有一次额外本地读取跳转，没有省略鉴权。不是公网速度承诺。

首页关键脚本1062400→338841B；工作区总传输3313259→2033443B。两次路由分块中，脚本字节与真实耗时均下降；请求数量反而增加，不能把请求数当作这次优化的主要指标。

## 护栏与边界

- 60/60采样成功；三页各1440/390两宽度可见文字逐字一致，最高像素差0.000966%，低于预设0.1%。
- 四入口、十个页面、列表搜索、手动录入对话框通过；页面文件加载失败时导航仍可用，重载后恢复。
- 压缩通过真实HTTP边界验证；正文解压后逐字相同。未登录401、错误、禁用gzip、HEAD、小响应、已有编码、媒体Range与JSON产物下载保持原行为。
- 目标为p75减半，本轮未达到。字体/CSS和有效制作内容仍是必要传输；不为追目标削减历史或改变视觉。这轮收口后优先验证真实生产链，不追加大范围性能重构。
- 上线前后真实网络样本单独记录，不能和限速实验混为一组；CrUX未取得，不能宣称真实用户p75通过。

## 线上观察

2026-10-07 上线前后各采集30次（每页10次），同一认证上下文、同一批制作数据、禁HTTP缓存，使用真实网络；它们不是同时交替配对的实验室样本。

| 页面 | 上线前 p50 / p75 / p95 | 上线后 p50 / p75 / p95 |
| --- | --- | --- |
| 创作台 | 5233.2 / 5290.7 / 5416.7ms | 3459.9 / 3527.8 / 3680.9ms |
| 制作记录 | 10641.3 / 11133.9 / 15735.2ms | 8909.6 / 13913.2 / 16538.7ms |
| 制作工作区 | 8959.2 / 9299.4 / 10661.5ms | 5856.3 / 6038.8 / 7040.5ms |

创作台和工作区更快，但制作记录页的p75变慢25.0%，不能宣称全站线上提速。列表后测范围为4752.5–18603.2ms；补充一次资源拆解为3734.8ms，其中列表API为291.6ms，末段仍在加载中文字体。该单次样本只说明波动，不能替代原30次结果，也不足以排除回归。保留这项观察，不据此扩大网络或字体改造。CrUX仍无数据。

## 重跑与发布

`perf/bench/measure.mjs`只允许本地隔离地址、使用合成账号且不保存认证状态；`compare.py`核对同一数据的文字及像素护栏。原始数据、截图和用户制作资料不纳入公开仓库。棘轮采用5%噪声容差，使用同口径数据检查`ceilings.json`。

最终发布必须在完整npm、Python、打包和图谱检查后进行，普通推送main，由GitHub Actions验证并部署；随后核对实际release、容器健康、静态文件和原制作记录指纹。回滚用相应独立提交的revert，经同一发布链；不回滚或清理用户制作数据。
